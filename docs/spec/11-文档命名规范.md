# 文档命名规范

> 本文定义本项目全部文档的**中英双语命名方案**与**通用命名规则**。
> 适用范围：`docs/` 三层结构 + `.agent/logs/`；新文档一律按本文命名。
> 🔄 本轮：新增（spec 第 11 号）

---

## 一、通用命名规则（8 条）

| # | 规则 | 说明 |
|---:|---|---|
| 1 | **文件名统一小写** | ASCII 文件名全小写（`pdf-office.md` 而非 `PDF-Office.md`） |
| 2 | **分隔符统一连字符** | kebab-case；禁用下划线、空格、驼峰 |
| 3 | **编号前缀 `NN-`** | 两位数字 + 连字符，表示阅读顺序或域序号；编号即顺序，不跳号 |
| 4 | **词序：限定词在前，主题在后** | 中文「`06-数学金融`」↔ 英文「`06-math-finance`」，语序保持同构 |
| 5 | **只保留无歧义的业界缩写** | 允许：`API`/`SEO`/`PDF`/`AI`/`LLM`/`Web3`/`A11y`/`i18n`/`IA`/`LCP`/`CI`；其余一律不缩 |
| 6 | **语言变体用后缀** | 英文版加 `.en`，中文版无后缀（`DEVELOPMENT.md` / `DEVELOPMENT.en.md`） |
| 7 | **社区惯例文件保留全大写** | `README.md`、`CHANGELOG.md`、`LICENSE`、`CONTRIBUTING.md` |
| 8 | **扩展名统一** | 正文 `.md`，机器可读事件流 `.jsonl`，配置 `.yaml` / `.json` |

### 中英对应原则（避免生硬直译）

| 原则 | 反例 | 正例 |
|---|---|---|
| 取**功能**而非逐字 | `待决事项` → `waiting-items` | `08-open-decisions` |
| 用**业界既有术语** | `信息架构` → `information-structure` | `06-web-structure-and-ia`（IA 是标准术语） |
| 选**准确词**而非泛词 | `缺口清单` → `gap-list` | `05-gap-inventory`（含「盘点」义） |
| 保留**专有名原样** | `DevLog规范` → `development-log-spec` | `10-devlog-spec`（DevLog 是项目专名） |
| 与 **category slug 对齐** | `07-随机生成设计` → `generators-design` | `07-random-generation-design`（对齐 slug `random`） |

## 二、推荐方案：英文做文件名，中文做展示名

**推荐方案 A（默认）**

- **实际文件名**用英文 ASCII —— 跨平台、git/CI/脚本引用零成本，避免中文文件名在部分环境被转义（git 默认输出 `"\346\226\207..."`）。
- **中文名**作为文档 H1 标题与索引表展示名 —— 面向中文团队的可读名与检索词。

**备选方案 B**：若团队坚持中文文件名，可用中文名，但需接受 git 的 `core.quotepath=false` 配置依赖与脚本转义成本。

> 本项目现状：37 份文档为中文文件名，运行正常。**是否迁移到方案 A 由负责人决定**，本文两套命名均已给出，可直接使用。

## 三、常见文档类型 · 命名示例

| 类型 | 中文命名 | 英文命名 | 理由 |
|---|---|---|---|
| 说明文档（项目入口） | 文档中心 | `README.md` | 社区惯例全大写，工具链与平台自动识别 |
| 说明文档（使用手册） | 开发手册 | `DEVELOPMENT.md` | 全大写 + 无编号，表示顶层入口而非序列文档 |
| 接口文档 | 接口参考 | `api-reference.md` | `reference` 表明是查阅型契约说明，区别于教程型 guide |
| 接口文档（版本化） | 接口变更记录 | `api-changelog.md` | 前缀限定范围，避免与全局 CHANGELOG 混淆 |
| 设计文档 | 架构设计 | `design-architecture.md` | `design-` 前缀聚合设计类文档，主题置后 |
| 设计文档（提案） | 方案提案 | `rfc-001-tool-template.md` | RFC + 编号是技术提案的通用惯例 |
| 变更记录 | 变更日志 | `CHANGELOG.md` | 社区惯例全大写，生态工具默认读取此名 |
| 变更记录（阶段性） | 迁移核对报告 | `migration-audit-report.md` | 动作 + 对象 + 类型，语义自解释 |
| 规范文档 | 开发规范 | `development-conventions.md` | `conventions` 指团队约定，语气弱于 `standards` |
| 清单 / 台账 | 工具总表 | `tool-inventory.md` | `inventory` 强调「盘点全量」，区别于 `list` |
| 决策记录 | 架构决策记录 | `adr-001-vite-over-nextjs.md` | ADR 是架构决策的标准命名惯例 |
| 日志 | 开发日志 | `devlog.md` | 项目专名，无编号，追加式文件 |

## 五、迁移检查清单

若采纳方案 A（英文文件名），执行顺序：

1. `git mv` 逐个重命名，保留历史
2. 全量替换交叉引用（36 份文档内的相对链接）
3. 更新 `docs/README.md` 文档地图与查阅表
4. 更新 `DEVELOPMENT.md` / `DEVELOPMENT.en.md` 内的链接
5. 跑一次断链检查确认零断链
6. Windows 环境注意大小写不敏感，`PDF-Office.md` → `pdf-office.md` 需用 `git mv -f` 或两步重命名

> **注意**：当前 36 份文档含约 40 处交叉引用，批量重命名必须同步替换，否则断链。
