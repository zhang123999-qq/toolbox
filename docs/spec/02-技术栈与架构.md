## 二、分层架构

```
┌──────────────────────────────────────────────┐
│ 接入层 apps/web                              │
│ pages / components / layouts / app           │
├──────────────────────────────────────────────┤
│ 工具层 tools / features                      │
│ 具体工具实现 / 业务域通用逻辑                │
├──────────────────────────────────────────────┤
│ 注册层 catalog                               │
│ 元数据 / 分类 / 标签 / 路由 / 搜索索引       │
├──────────────────────────────────────────────┤
│ 能力层 lib / hooks / stores / services       │
│ 工具函数 / 状态 / 存储 / 导出 / API          │
├──────────────────────────────────────────────┤
│ 执行层 workers / wasm                        │
│ Web Worker / WASM 模块                       │
├──────────────────────────────────────────────┤
│ 资源层 public / assets / styles              │
├──────────────────────────────────────────────┤
│ 工程层 scripts / tests / deploy / docs       │
└──────────────────────────────────────────────┘
```

**每层职责边界：**

| 层     | 允许依赖               | 禁止                        |
| ------ | ---------------------- | --------------------------- |
| 接入层 | 工具层、注册层、能力层 | 直接调 WASM/Worker 原始 API |
| 工具层 | 注册层、能力层、执行层 | 跨工具互相 import           |
| 注册层 | 无（纯元数据）         | 引入任何 UI 或副作用        |
| 能力层 | 执行层                 | 依赖具体工具实现            |
| 执行层 | WASM 模块              | 依赖 React                  |

> 分层与 `03-目录结构.md` 的目录树一一对应：接入层=`app`/`pages`/`components`，
> 工具层=`tools`/`features`，注册层=`catalog`，能力层=`lib`/`hooks`/`stores`/`services`，
> 执行层=`workers`/`wasm`，资源层=`public`/`styles`/`assets`，工程层=`scripts`/`tests`/`deploy`。

## 三、WASM 方案

| 用途              | 方案                     | 目录                  |
| ----------------- | ------------------------ | --------------------- |
| 图片处理          | Rust→WASM `photon-rs`    | `src/wasm/photon`     |
| 大图 / 批量缩略图 | `wasm-vips`              | `src/wasm/wasm-vips`  |
| 音视频转码        | Emscripten `ffmpeg.wasm` | `src/wasm/ffmpeg`     |
| OCR               | `tesseract.js`           | `src/wasm/tesseract`  |
| PDF 写            | `pdf-lib`                | `src/wasm/pdf-lib`    |
| PDF 读            | `pdfjs-dist`             | `src/wasm/pdfjs`      |
| Office 渲染       | `@neo-office/renderer`   | `src/wasm/neo-office` |
| SQLite            | SQLite WASM              | `src/wasm/sqlite`     |
| 本地 LLM          | `wllama` + WebGPU        | `src/wasm/wllama`     |

**加载策略（硬约束）：**

- 所有 WASM **不得打进主包**，一律懒加载
- 大体积模块（ffmpeg / wasm-vips / wllama）放独立 CDN 或子路径
- 统一通过 `packages/wasm` 的 `loadWasm()` 入口加载并缓存

## 四、Worker 分层策略

以下任务**全部入 Web Worker**，避免阻塞主线程：

| Worker             | 承担任务                         |
| ------------------ | -------------------------------- |
| `image.worker.ts`  | 图片压缩、批处理、滤镜、格式转换 |
| `pdf.worker.ts`    | PDF 合并/拆分/压缩/OCR 渲染      |
| `office.worker.ts` | Office 文档解析与渲染            |
| `media.worker.ts`  | 音视频编码、转码、抽帧           |
| `ai.worker.ts`     | 本地 LLM 推理、嵌入计算          |
| `hash.worker.ts`   | 大文件哈希、校验和               |

## 五、静态可行性标签体系

| 标签  | 含义                  | 目标占比 |
| ----- | --------------------- | -------: |
| **A** | 纯 JS                 |        — |
| **B** | WASM                  |        — |
| **C** | WebCrypto / WebCodecs |        — |
| **D** | 需用户 API / Key      |   约 10% |
| **E** | 需后端                |    约 2% |

## 六、核心架构原则

```
catalog（唯一真源）
   ├─→ routes.ts        路由生成
   ├─→ 首页分组展示
   ├─→ search-index.ts  搜索索引（Fuse / Orama）
   ├─→ 标签筛选
   └─→ 工具元数据（feasibility / priority / worker / wasm / api）
```

**新增工具 = 建文件夹 + 注册 `meta.ts`**，路由、首页、分类页、搜索索引、sitemap 全自动更新，无需手改任何路由表。
