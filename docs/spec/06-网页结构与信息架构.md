> 来源：用户提供的《工具库网页结构优化方案》

## 一、核心结论

| 优化项 | 上一版问题 | 优化后 |
|---|---|---|
| 页面数量 | 1070 页太散 | 收敛为 **870 工具页 + 54 聚合/静态页 = 924 页**，标签/子类用查询参数 |
| 搜索 | 只做 Cmd+K | **三层搜索**：首页 + 全局 Cmd+K + 工具页内 |
| 工具页 | 统一模板 | 抽象为 **6 种布局模板**，按工具类型匹配 |
| 分类 | 20 个平铺 | **4 大组 + 20 域 + 60 子类**，三级信息架构 |
| URL | 多套规则 | **统一 `/tools/:slug` + 查询参数**，减少页面爆炸 |
| 性能 | 通用策略 | **首屏 < 50KB、工具按需 < 30KB、WASM 延迟加载** |
| SEO | 分类页为主 | **工具页 + FAQ + JSON-LD + 内链**四件套 |
| 移动端 | 简单响应式 | **工具操作区触屏优先 + 底部 Tab + 手势** |

## 二、信息架构：三层结构

```text
第一层：4 大组（用户心智）
├── 开发编码    文本、编码、数据、开发、时间、网络
├── 设计媒体    图片、颜色、音视频、可视化、游戏
├── 办公文档    PDF、Office、表格、文档转换
└── 生活学习    数学、金融、健康、教育、趣味

第二层：20 个域（分类页）
第三层：60+ 子类（筛选器，不单独建页）
```

**为什么改：** 20 个分类对普通用户太多，4 大组更符合直觉；子类用筛选器而非独立页，减少 60 个低质页面。

### 4 大组 ↔ 20 域映射

| 大组 | slug | 包含域 | 域数 | 工具数 |
|---|---|---|---:|---:|
| 开发编码 | `dev` | 1 文本、2 编码、3 数据、4 运维、5 时间、12 网络 | 6 | 360 |
| 设计媒体 | `design` | 8 图片、7 随机设计、10 音视频、13 可视化、18 游戏 | 5 | 200 |
| 办公文档 | `office` | 9 PDF/Office | 1 | 60 |
| 生活学习 | `life` | 6 数学、11 AI、14 Web3、15 无障碍、16 自动化、17 扩展、19 边缘、20 教育 | 8 | 250 |

> ⚠️ **口径冲突待确认**：原文「4 大组」描述列出的是「文本、编码、数据、开发、时间、网络 / 图片、颜色、音视频、可视化、游戏 / PDF、Office、表格、文档转换 / 数学、金融、健康、教育、趣味」，共 **18 个条目**，且「办公文档」只覆盖 1 个域（60 个工具），而「生活学习」塞了 8 个域（250 个工具）。
>
> 上表是我按 4 组↔20 域的合理归属做的映射，**其中「颜色设计」「健康生活」「文档转换」三个子组在原 20 域中无对应实体**，需要在开工前明确：是新增域，还是并入现有域。

## 五、工具页 6 种模板

**核心优化：** 870 个工具不套同一模板，抽象为 6 种布局，按工具类型自动匹配。

| 模板 | 名称 | 适用工具 | 布局 | 示例 |
|---|---|---|---|---|
| **T1** | 单栏 | 输入→输出简单工具 | 上输入下输出 | uuid、timestamp、password-generator |
| **T2** | 双栏 | 转换/对比类 | 左右分栏，宽度可拖动 | json-formatter、text-diff、base64-encode |
| **T3** | 多面板 | 复杂参数工具 | 输入 + 选项 + 输出 | regex-tester、image-compress、loan |
| **T4** | 全屏 | 画布类 | 全屏画布 + 悬浮工具栏 | image-crop、map-editor、pixel-art |
| **T5** | 向导 | 多步骤工具 | 步骤条 + 分步表单 | id-photo、invoice-gen、resume |
| **T6** | 仪表盘 | 数据监控类 | 多卡片网格 | seo-audit、api-test、api-monitor |

### 模板匹配规则（建议写入 `meta.ts`）

```ts
type ToolMeta = {
  // ... 既有字段
  template: 'T1' | 'T2' | 'T3' | 'T4' | 'T5' | 'T6'
  group: 'dev' | 'design' | 'office' | 'life'
```

**默认匹配逻辑：**

- 多卡片监控面板 → T6
- 输入输出同构（转换/对比） → T2
- 其余 → T1

## 九、性能策略

| 指标 | 目标 | 策略 |
|---|---:|---|
| 首屏 JS | < 50KB | 首页只加载分类 + 热门，不全量加载 |
| 工具页 JS | < 30KB | 每工具独立 chunk，按需加载 |
| 搜索索引 | < 50KB gzip | 构建时生成，只含 id/title/tags |
| WASM | 延迟加载 | 首次使用才下载，CacheFirst |
| LCP | < 1.5s | 首页 Hero 静态渲染 |
| TTI | < 2s | 工具页骨架屏 + 懒加载 |
| CLS | < 0.1 | 预留工具区高度 |

### 加载策略

```text
首页：
  HTML + CSS + 核心 JS（< 50KB）
  ↓
  分类 + 热门（静态数据，内联）
  ↓
  搜索索引（延迟 1s 或首次交互加载）

工具页：
  HTML + CSS + 工具 chunk（< 30KB）
  ↓
  纯 JS 工具：直接可用
  WASM 工具：显示"加载中"，后台下载 WASM
  Worker 工具：主线程可用，Worker 后台启动

搜索：
  Cmd+K 打开时才加载 Orama 索引
  索引缓存到 IndexedDB
```

```text
│ [格式化][清空][示例] │   →    │ [复制][下载][返回]  │
└─────────────────────┘        └─────────────────────┘
```

**要点：** 移动端不复用桌面双栏，改为「输入/输出」两态切换，底部操作栏始终固定。

## 十五、最终建议（7 条）

1. **信息架构按用户心智分 4 组**，不按技术分类平铺 20 个。
2. **工具页用 6 种模板**，不套同一套布局。
3. **搜索做三层**，首页 + Cmd+K + 工具内。
4. **页面收敛**，标签/子类用查询参数，减少低质页面。
5. **性能分层**，首屏轻、工具按需、WASM 延迟。
6. **SEO 四件套**，Title + Description + H1 + JSON-LD。
7. **移动端触屏优先**，底部 Tab + 全屏工具 + 固定操作栏。
