# 开发规范

---

## 一、新增工具流程（6 步）

1. 新建 `src/tools/my-tool/` 目录
2. 写 `meta.ts` 注册元数据
3. 实现 `Tool.tsx`，必要时加 `worker.ts` / `wasm.ts`
4. 执行 `pnpm generate:catalog`
5. 路由、首页、分类页、搜索索引、sitemap **自动更新**
6. 执行 `pnpm test && pnpm build`

> 关键：**永远不要手写路由表**。路由由 `catalog/routes.ts` 从 `meta.ts` 聚合生成。

## 二、`meta.ts` 模板

```ts
export const meta = {
  id: 'json-formatter',
  slug: 'json-formatter',
  title: 'JSON 格式化',
  category: 'data-format',
  group: 'dev', // dev / design / office / life
  template: 'T2', // T1 单栏 / T2 双栏 / T3 多面板 / T4 全屏 / T5 向导 / T6 仪表盘
  tags: ['json', 'format', 'validate'],
  priority: 'P0',
  feasibility: 'A', // A 纯 JS / B WASM / C WebCrypto / D 用户 API / E 需后端
  worker: false,
  wasm: false,
  api: false,
} as const

export type Meta = typeof meta
```

### 字段约束

| 字段          | 必填 | 约束                                                               |
| ------------- | ---- | ------------------------------------------------------------------ |
| `id`          | ✅   | 全局唯一，kebab-case                                               |
| `slug`        | ✅   | URL 片段，与 `id` 保持一致（除非有历史包袱）                       |
| `title`       | ✅   | 中文展示名                                                         |
| `category`    | ✅   | 必须是 `catalog/categories.ts` 中已登记的域                        |
| `group`       | ✅   | `dev` / `design` / `office` / `life`，必须与 `category` 的归属一致 |
| `template`    | ✅   | `T1`–`T6`，决定工具页用哪套布局                                    |
| `tags`        | ✅   | 至少 2 个，全小写，用于搜索                                        |
| `priority`    | ✅   | `P0` / `P1` / `P2` / `P3`                                          |
| `feasibility` | ✅   | `A` / `B` / `C` / `D` / `E`                                        |
| `worker`      | ✅   | 布尔                                                               |
| `wasm`        | ✅   | 布尔（用到的模块记在 `wasm.ts`）                                   |
| `api`         | ✅   | 布尔。**为 `true` 时 UI 必须显示「需自备 API/Key」提示**           |

`scripts/check-tools.ts` 会在 CI 中校验以上字段，缺一即失败。

### 模板匹配规则

| 条件                      | 模板        |
| ------------------------- | ----------- |
| 有画布 / 拖拽交互         | `T4` 全屏   |
| 有 3+ 参数选项            | `T3` 多面板 |
| 多步骤产出物              | `T5` 向导   |
| 多卡片监控面板            | `T6` 仪表盘 |
| 输入输出同构（转换/对比） | `T2` 双栏   |
| 其余                      | `T1` 单栏   |

详见 [`06-网页结构与信息架构.md`](06-网页结构与信息架构.md) §5。

## 三、工具目录规范

```text
src/tools/<tool-id>/
├── meta.ts        # 元数据（必需）
├── Tool.tsx       # UI 入口（必需）
├── schema.ts      # Zod 输入/输出校验（必需）
├── utils.ts       # 纯函数，便于单测（必需）
├── worker.ts      # 可选：重任务放 Web Worker
├── wasm.ts        # 可选：WASM 模块加载
├── test.ts        # 单测/组件测试（必需）
└── README.md      # 使用说明、数据流向、限制（必需）
```

### 分层约束

- `utils.ts` 必须是**纯函数**，不依赖 React、不触碰 DOM，便于单测
- `Tool.tsx` 只做 UI 组装，业务逻辑下沉到 `utils.ts` / `features/`
- `worker.ts` 与 `wasm.ts` **不得** import React
- 工具之间**禁止**互相 import；共用逻辑一律上提到 `features/` 或 `lib/`

## 四、数据流

```text
用户访问 /tools/json-formatter
        │
        ▼
app/router 匹配 catalog/routes.ts
        │
        ▼
catalog/loader.ts 懒加载 tools/json-formatter/Tool.tsx
        │
        ▼
Tool.tsx 使用 hooks / lib / services
        │
        ├── 轻任务：纯 JS 直接处理
        ├── 重任务：workers/image.worker.ts
        ├── 编解码：wasm/pdfjs、wasm/ffmpeg
        └── 需 Key：services/api 请求用户自备 API
        │
        ▼
结果返回 UI → 复制 / 下载 / 导出
        │
        ▼
收藏 / 历史写入 stores + IndexedDB
```

## 五、命名规范

| 对象           | 规则                           | 示例                          |
| -------------- | ------------------------------ | ----------------------------- |
| 工具目录       | kebab-case                     | `json-formatter`、`pdf-merge` |
| React 组件文件 | PascalCase                     | `Tool.tsx`、`JsonEditor.tsx`  |
| 工具函数文件   | kebab-case                     | `use-tool.ts`、`utils.ts`     |
| Hook           | `useXxx`                       | `useWorker`、`useFavorites`   |
| Store          | `<域>-store.ts`                | `favorite-store.ts`           |
| Worker         | `<域>.worker.ts`               | `image.worker.ts`             |
| Zod Schema     | 文件内导出 `<tool>InputSchema` | `jsonFormatterInputSchema`    |

## 六、开发命令（约定）

```bash
pnpm dev                 # 启动 apps/web 开发服务
pnpm build               # 全仓构建
pnpm test                # 全仓单测
pnpm test:e2e            # Playwright E2E
pnpm lint                # eslint
pnpm typecheck           # tsc --noEmit
pnpm generate:catalog    # 扫描 tools 生成 catalog
pnpm generate:sitemap    # 生成 sitemap.xml
pnpm check:tools         # 校验工具元数据完整性 + 重复检测
pnpm build:wasm          # 构建/拷贝 WASM 模块
```

---

## 七、CI 门禁

`.github/workflows/ci.yml` 必须通过：

1. `pnpm lint`
2. `pnpm typecheck`
3. `pnpm check:tools` —— 元数据完整性 + 重复工具检测
4. `pnpm test`
5. `pnpm build`

`.github/workflows/lighthouse.yml` 负责性能 / SEO / 无障碍检测。

---

## 八、红线（不可违反）

1. **不得手写路由表** —— 一律由 catalog 生成
2. **不得把 WASM 打进主包** —— 全部懒加载
3. **不得跳过后端校验** —— 所有输入必须过 Zod
4. **`api: true` 的工具不得隐藏数据流向** —— 页面须明示「需自备 API/Key」
5. **不得上传用户数据** —— 纯前端处理是本项目立身之本
6. **不得工具间互相 import** —— 共用逻辑上提
7. **不得绕过模板系统自造布局** —— 必须用 T1–T6 之一
8. **不得新增独立标签页 / 子类页** —— 一律走查询参数
