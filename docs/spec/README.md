## 一、项目定位

一个**可检索、可分类、可离线、可扩展的纯静态工具平台**。

核心公式：

```
catalog 注册中心 + 元数据 + 标签搜索 + WASM/Worker 分层 + PWA 离线
```

三条硬性原则：

1. **本地优先** —— 数据不上传，纯前端处理
2. **纯静态部署** —— 无后端，构建产物可直接托管
3. **可扩展** —— 新增工具 = 建文件夹 + 注册元数据，路由/首页/搜索自动更新

## 六、工具元数据规范（强制）

每个工具的 `meta.ts` 必须包含：

```ts
export const meta = {
  id: 'json-formatter', // 全局唯一，kebab-case
  slug: 'json-formatter', // URL 片段
  title: 'JSON 格式化', // 展示名
  category: 'data-format', // 一级域（对应 features 目录名）
  group: 'dev', // 4 大组：dev / design / office / life
  template: 'T2', // 6 种页面模板：T1-T6
  tags: ['json', 'format', 'validate'],
  priority: 'P0', // P0 / P1 / P2 / P3
  feasibility: 'A', // A/B/C/D/E
  worker: false, // 是否入 Web Worker
  wasm: false, // 是否用 WASM
  api: false, // 是否需要用户 API/Key
}
```

> `group` 与 `template` 为网页结构方案新增字段，详见 [`06-网页结构与信息架构.md`](06-网页结构与信息架构.md) §5。

### 可行性标签定义

| 标签  | 含义                  | 目标占比 |
| ----- | --------------------- | -------: |
| **A** | 纯 JS                 |        — |
| **B** | WASM                  |        — |
| **C** | WebCrypto / WebCodecs |        — |
| **D** | 需用户自备 API / Key  |   约 10% |
| **E** | 需后端                |    约 2% |

> **D 类必须在工具页明确标注「需用户自备 API/Key」与数据流向，不得隐藏。**
