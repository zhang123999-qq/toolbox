# 背景移除 background-remove（#457）

## 用途 | Purpose

- 本地移除图片背景并输出透明 PNG，全程不上传。
- Remove image backgrounds locally and export a transparent PNG, no upload.

## 两种模式 | Modes

| 模式                  | 原理                                                                                                                                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 边缘抠除 edge（默认） | 采样**四角 + 四条边中点**共 8 个像素的 RGB 均值作为背景色估计；从**四条边的所有像素**出发做洪水填充（BFS），只穿过与背景色欧氏距离 ≤ 容差阈值的像素，把连通域置透明。适合纯色/渐变背景、主体不触边的人像与产品图。 |
| 色度键 chroma         | 全图遍历：与用户所选**目标颜色**（色板 `#rrggbb`）距离 ≤ 容差阈值的像素置透明，不考虑连通性。适合绿幕/蓝幕抠像。                                                                                                   |

两种模式都用 **RGB 欧氏距离的平方**比较（`colorDistanceSq`，避免开方），
阈值由容差换算而来（见下）。

## 容差映射 | Tolerance mapping

容差 `tolerance`（0–100，默认 25）→ 颜色距离平方阈值：

```
distSq = ((tolerance / 100) × 441.67)²
```

- `441.67 = √(3 × 255²)`：RGB 立方体对角线长度，即黑到白的最大欧氏距离。
- `tolerance = 0` → 阈值 `0`：只移除与背景色/目标色**完全相同**的像素。
- `tolerance = 100` → 阈值 ≈ `195073`：覆盖整个 RGB 色域（边缘抠除会把整图抠透明）。
- `tolerance = 25`（默认）→ 阈值 ≈ `12192`，约相当于单通道 110 的色差。

若抠除后**没有像素被置透明**（`removed = 0`），界面会提示
「未检测到可移除的背景，请调大容差或换色度键模式」——这是合法分支，
常见于图片本身已全透明、或背景与主体颜色差异过大。

## 技术路线决策 | Tech decision

- **纯 JS 实现，不用 ML 模型。** 文档技术路线为纯 JS：`@imgly/background-removal`
  等 ML 方案体积约 **40MB+**、首次使用需下载模型，不符合本项目
  「纯本地、轻量、无网络依赖」的定位。
- 因此采用**边缘洪水填充 + 色度键**的纯 Canvas 实现，
  `feasibility: 'A'`，`worker / wasm / api` 全为 false，`deps: []`。
- 代价：对复杂背景、发丝级边缘、主体触边的情况，效果不如 ML 语义分割；
  这是轻量定位下的已知取舍，见「边界」。

## 输入 | Input

- 图片文件：PNG / JPEG / WebP / GIF / BMP / AVIF，单文件上限 50MB。
- Image file: PNG / JPEG / WebP / GIF / BMP / AVIF, max 50MB per file.

## 选项 | Options

| 选项                 | 说明                                                     |
| -------------------- | -------------------------------------------------------- |
| 模式 mode            | edge（边缘抠除）/ chroma（色度键）                       |
| 容差 tolerance       | 0–100，默认 25；越大越「宽容」，抠得越多                 |
| 目标颜色 targetColor | `#rrggbb` 色板，仅色度键模式使用，默认 `#00ff00`（绿幕） |

## 输出 | Output

- 原图 / 抠除结果前后对比（棋盘格衬底展示透明效果）、已移除像素数统计。
- 一键下载透明 PNG（文件名 `原名-nobg.png`）。
- Before/after comparison on a checkerboard backdrop, removed-pixel count,
  one-click transparent PNG download (`<name>-nobg.png`).

## 性能建议 | Performance

- 洪水填充为 **O(宽 × 高)** 同步计算，主线程执行：1080p（约 200 万像素）
  通常在百毫秒级完成；4K（约 830 万像素）约需数百毫秒并占用约
  `宽×高×(4+1+4)` 字节临时内存（像素拷贝 + 访问标记 + 显式栈）。
- 建议处理长边 **≤ 2000px** 的图片；超大图可先用本站的「图片压缩」
  （image-compress #421）缩小后再抠。
- 显式栈代替递归，不会爆栈。

## 边界 | Limits

- 全程本地 Canvas 处理，不上传。
- JPEG 等无透明通道的格式输入正常，输出一律为透明 PNG。
- 复杂背景、主体触碰图片边缘、背景与主体颜色相近时，边缘抠除可能
  抠多或抠少——此时调大容差或改用色度键模式。
- 发丝、半透明（婚纱、玻璃）等细节无法精确保留（非 ML 方案的固有局限）。
- GIF 动图只处理第一帧（Canvas 限制）。
- 图片本身已全透明、或没有任何像素落入容差时，提示用户调大容差或换模式。

## 数据流向 | Data flow

文件 → 内存 Canvas（getImageData → 纯函数抠除 → putImageData）→ PNG Blob → 下载；不经过网络。
