# ECDSA 签名

椭圆曲线数字签名（ECDSA）签名与验签，支持 P-256 / P-384 / P-521。

## 用途

给文本做 ECDSA 签名并用公钥核对。适合验证 JWT 的 ES256/ES384/ES512、调试 WebAuthn 与
各类区块链/硬件密钥产出的签名。

## 输入

| 字段         | 类型   | 约束              | 说明           |
| ------------ | ------ | ----------------- | -------------- |
| `text`       | string | 最大 200,000 字符 | 待签数据或原文 |
| `privateKey` | string | PEM（PKCS#8）     | 签名时使用     |
| `publicKey`  | string | PEM（SPKI）       | 验签时使用     |
| `signature`  | string | Base64 / hex      | 验签时使用     |

## 输出

| 字段   | 类型   | 说明                                                                 |
| ------ | ------ | -------------------------------------------------------------------- |
| `text` | string | 原始 `r‖s` 签名（按选项编码），或验签结论（`验签通过` / `验签失败`） |

## 选项

| 选项        | 取值                        | 默认    | 说明                               |
| ----------- | --------------------------- | ------- | ---------------------------------- |
| `direction` | sign / verify               | sign    | 签名或验签                         |
| `curve`     | P-256 / P-384 / P-521       | P-256   | 必须与密钥一致                     |
| `hash`      | SHA-256 / SHA-384 / SHA-512 | SHA-256 | 必须与验签侧一致，不一致会验签失败 |
| `encoding`  | base64 / hex                | base64  | 签名的呈现编码                     |

## 限制

- 输出的是**原始 `r‖s`** 签名（P-256 为 64 字节），不是 ASN.1 DER 序列。
  JWT 的 ES256 用的正是这种格式；OpenSSL / Java 默认产出 DER，需要先转换
- ECDSA 签名含随机 nonce：**同样的输入每次签名结果都不同**，这是正常的安全特性，
  不能用「两次签名相同」来判定实现是否正确（Ed25519 / RSA PKCS#1 v1.5 才是确定性的）
- 只支持 WebCrypto 的三条 NIST 曲线，**不含 secp256k1**
- 页面内置的演示密钥对仅供试用，**不要**用于真实数据

## 数据流向

**纯本地处理。** 私钥与数据只在浏览器内存里参与运算，不发送任何网络请求。
`meta.api = false`，无需自备 API/Key。

## 示例

输入（签名方向，演示私钥）：

```text
这是一段需要 ECDSA 签名的数据。
```

输出（P-256 / SHA-256 / base64，每次不同）：

```text
<86 个 Base64 字符，解码后 64 字节>
```
