# 版本号生成

输入当前版本号，按 bump 类型算出下一个 SemVer，并附一段 CHANGELOG 建议条目。

## 用途

发版时不用心算 `1.4.2` patch 之后是几、`-beta.0` 再下一版是 `-beta.1` 还是 `-rc.0`。
选好 bump 类型即可。

## 输入

| 字段   | 类型   | 约束                      |
| ------ | ------ | ------------------------- |
| `text` | string | 当前版本号，最大 500 字符 |

## 选项

| 选项 key | 界面       | 说明                                                                |
| -------- | ---------- | ------------------------------------------------------------------- |
| `bump`   | bump 类型  | major / minor / patch / premajor / preminor / prepatch / prerelease |
| `preId`  | 预发布标签 | 默认 `beta`，如 `rc` / `alpha`                                      |

## 规则

| bump       | 输入 `1.4.2` 输出 | 含义                                                            |
| ---------- | ----------------- | --------------------------------------------------------------- |
| major      | `2.0.0`           | 不兼容变更                                                      |
| minor      | `1.5.0`           | 向后兼容新功能                                                  |
| patch      | `1.4.3`           | 向后兼容修复                                                    |
| premajor   | `2.0.0-beta.0`    | 下个大版本预发布                                                |
| preminor   | `1.5.0-beta.0`    | 下个小版本预发布                                                |
| prepatch   | `1.4.3-beta.0`    | 下个补丁预发布                                                  |
| prerelease | `1.4.3-beta.0`    | 当前是正式版 → 进预发布；当前是 `1.4.2-beta.0` → `1.4.2-beta.1` |

## 数据流向

**纯本地处理。** 无网络请求。`meta.api = false`。

## 示例

输入 `1.4.2`，bump 选 `minor`：

```text
当前版本：1.4.2
bump 类型：minor —— 向后兼容的新功能：递增 minor，patch 归零
下一版本：1.5.0

# CHANGELOG 建议条目
## [1.5.0] - 2026-09-26
- （按实际变更填写：新增 / 修复 / 破坏性变更）
```
