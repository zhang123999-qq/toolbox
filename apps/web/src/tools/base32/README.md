# Base32 编解码

RFC 4648 Base32 编解码，大小写不敏感。

## 用途

Base32 只使用 `A-Z` 与 `2-7`，不含 `0/1/8/9`，因此不会与 `O/I/B` 混淆，
也无大小写歧义——适合人工抄写、口述或在不区分大小写的系统里传输。
常见于 TOTP 密钥、部分云服务的恢复码、按域名分目录的存储布局。

## 输入

| 字段   | 类型   | 约束              |
| ------ | ------ | ----------------- |
| `text` | string | 最大 200,000 字符 |

编码时为任意文本；解码时为 Base32 字符串（大小写、空格、填充均可随意）。

## 输出

| 字段   | 类型   | 说明                              |
| ------ | ------ | --------------------------------- |
| `text` | string | 编码后为 Base32；解码后为原始文本 |

## 选项

| 选项        | 取值            | 默认   | 说明       |
| ----------- | --------------- | ------ | ---------- |
| `direction` | encode / decode | encode | 编码或解码 |

## 限制

- 使用 RFC 4648 标准字母表；Base32hex（用 `0-9A-V`）等变体未实现
- 解码要求结果必须是合法 UTF-8；二进制内容无法还原为文本，会明确报错
- 解码不接受字母表之外的字符（`0/1/8/9` 会报错），不做静默丢弃

## 数据流向

**纯本地处理。** 输入内容仅在浏览器内存中处理，不发送任何网络请求，不写入服务端。
`meta.api = false`，无需自备 API/Key。

## 示例

输入：

```text
hello
```

输出（encode）：

```text
NBSWY3DP
```
