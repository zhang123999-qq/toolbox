# ECC 加密

基于 ECDH 的椭圆曲线密钥协商：用「己方私钥 + 对方公钥」推导共享密钥，也能直接生成密钥对。

## 用途

理解与验证 ECDH 协商：生成一对密钥、把公钥发给对方、用对方公钥算出共享密钥 Z。
也可用于核对其它语言（OpenSSL / Node / Go）产出的 PEM 能否互相协商。

## 输入

| 字段         | 类型   | 约束          | 说明                                   |
| ------------ | ------ | ------------- | -------------------------------------- |
| `text`       | string | 最大 200,000  | 仅作触发用：协商与生成都不消费它的内容 |
| `privateKey` | string | PEM（PKCS#8） | 己方私钥，协商时必填                   |
| `publicKey`  | string | PEM（SPKI）   | 对方公钥，协商时必填                   |

## 输出

| 字段   | 类型   | 说明                                                            |
| ------ | ------ | --------------------------------------------------------------- |
| `text` | string | 协商出的共享密钥（base64 / hex），或生成出的公钥 + 私钥两份 PEM |

## 选项

| 选项        | 取值                  | 默认   | 说明                      |
| ----------- | --------------------- | ------ | ------------------------- |
| `direction` | derive / generate     | derive | 协商共享密钥 / 生成密钥对 |
| `curve`     | P-256 / P-384 / P-521 | P-256  | NIST 曲线，两边必须一致   |
| `encoding`  | base64 / hex          | base64 | 共享密钥的呈现编码        |

## 限制

- 只支持 WebCrypto 提供的三条 NIST 曲线；**secp256k1（比特币）不在其中**，浏览器原生不支持
- 输出的是 ECDH 原始共享密钥 Z（P-256 为 32 字节）。真实协议里应再过 HKDF 才作为对称密钥，
  本工具如实输出原始值，方便与其它实现逐字节对照
- 严格来说 ECDH 是**密钥协商**而不是加密；WebCrypto 未提供 ECIES，故没有「直接用公钥加密文本」
- 页面内置的演示密钥对仅供试用，**不要**用于真实数据

## 数据流向

**纯本地处理。** 私钥只在浏览器内存里参与运算，不发送任何网络请求。
`meta.api = false`，无需自备 API/Key。

## 示例

输入（协商方向，演示密钥对）：

```text
己方私钥 = DEMO_PRIVATE_KEY，对方公钥 = DEMO_PUBLIC_KEY
```

输出（P-256 / base64）：

```text
koUH48K8QJoy6DOIyAFXfpChmIlyRbKhtSbrn03LfL8=
```
