# 时区转换

把「某一个时区墙上看到的时间」精确换算成另一个时区的墙上时间，夏令时自动处理。

## 用途

跨时区开会、排期时最容易搞错的就是「北京下午 3 点是纽约几点」。
本工具接收一个墙上时间串 + 源时区 + 目标时区，输出换算后的时间、对应 UTC、以及 Unix 秒。
DST（夏令时）完全交给运行时的 `Intl`，不手写任何偏移表。

## 输入

| 字段   | 类型   | 约束                        |
| ------ | ------ | --------------------------- |
| `text` | string | 墙上时间，最大 200,000 字符 |

支持 `YYYY-MM-DD`、`YYYY/MM/DD`，可附加 `HH:mm` 或 `HH:mm:ss`（空格或 `T` 分隔）。
例如 `2026-09-27 15:30:00`。解析不了会直接报错，不会静默出 `Invalid Date`。

## 输出

| 字段   | 类型   | 说明                                        |
| ------ | ------ | ------------------------------------------- |
| `text` | string | 源时间 / 目标时间 / UTC 时间 / Unix 秒 四行 |

```text
源时间：2026-09-27 15:30:00（Asia/Shanghai，UTC+08:00）
目标时间：2026-09-27 03:30:00（America/New_York，UTC-04:00）
UTC 时间：2026-09-27 07:30:00
Unix 秒：1790494200
```

## 选项映射

| 选项 key   | 界面标签 | 语义                         |
| ---------- | -------- | ---------------------------- |
| `fromZone` | 源时区   | 输入墙上时间所在的 IANA 时区 |
| `toZone`   | 目标时区 | 要换算到的 IANA 时区         |

## 实现规则 / 算法

1. **解析墙上时间**：正则抽取 年/月/日/时/分/秒，并做区间校验（月 1–12、日 1–31、时 0–23…），
   避免 `new Date` 把 `2026-13-40` 静默进位成有效日期。
2. **墙上时间 → UTC 时刻（反推偏移）**：
   - 先把墙上分量当作 UTC 得到一个「猜测时刻」；
   - 用 `Intl.DateTimeFormat#formatToParts` 取出源时区在该猜测时刻的墙上时间，
     与猜测时刻做差，得到此时源时区相对 UTC 的偏移；
   - 减去偏移得到真实 UTC 时刻；
   - 在 DST 跳变日附近，再按修正后的时刻复查一次偏移，两次迭代即落在正确偏移上。
3. **UTC 时刻 → 目标时区墙上时间**：再次用 `formatToParts` 取出目标时区的分量。
4. 全程 IANA 名 + `Intl`，DST 由 ICU 数据决定。

## 浏览器 / 运行时边界

- 时区规则（尤其未来年份的 DST 起止）来自运行时 ICU；各国改 DST 政策后需升级浏览器/Node。
- 不接受 `CST`、`EST`、`GMT+8` 这类缩写或固定偏移，必须用 IANA 名。
- 「不存在的本地时间」（DST 跳时钟拨快时跳过的那一小时）会按 Intl 的边界规则落到相邻时刻，
  本工具不额外做「该时间不存在」提示——如需严格判断可对比往返偏移。

## 示例

输入：

```text
2026-09-27 15:30:00
```

选项：源时区 `Asia/Shanghai`，目标时区 `America/New_York`。

输出：

```text
源时间：2026-09-27 15:30:00（Asia/Shanghai，UTC+08:00）
目标时间：2026-09-27 03:30:00（America/New_York，UTC-04:00）
UTC 时间：2026-09-27 07:30:00
Unix 秒：1790494200
```
