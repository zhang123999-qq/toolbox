# HOTP 生成

按计数器生成一次性口令（HOTP，RFC 4226）——每用一次计数器 +1，口令随之改变。

## 用途

核对硬件令牌（YubiKey 的 HOTP 槽位）、银行口令卡这类**靠计数器**而非时钟的一次性口令：
填入密钥与计数器，看算出来的口令是否和服务端/设备一致。

## 输入

| 字段      | 类型   | 约束              | 说明                  |
| --------- | ------ | ----------------- | --------------------- |
| `text`    | string | 最大 200,000 字符 | Base32 共享密钥       |
| `counter` | string | 非负整数          | 计数器，从 0 开始递增 |

## 输出

| 字段   | 类型   | 说明                                        |
| ------ | ------ | ------------------------------------------- |
| `text` | string | 口令 + 一行参数说明（位数 / 计数器 / 摘要） |

## 选项

| 选项        | 取值                   | 默认 | 说明                            |
| ----------- | ---------------------- | ---- | ------------------------------- |
| `digits`    | 6 / 8                  | 6    | 口令位数                        |
| `algorithm` | SHA1 / SHA256 / SHA512 | SHA1 | HMAC 摘要；RFC 4226 只定义 SHA1 |

## 限制

- 与 TOTP 的区别：HOTP **不依赖时钟**，口令在计数器推进前一直有效
- 计数器需要你自己维护：客户端每生成一次 +1，服务端允许一定窗口（通常 ±3）容差
- 只支持 Base32 密钥；`otpauth://` URI 请先把 `secret=` 的值抠出来
- 8 位模式是 6 位模式的扩展：同一密钥与计数器下，8 位结果的后 6 位就是 6 位口令

## 数据流向

**纯本地处理。** 密钥只在浏览器内存里参与运算，不发送任何网络请求。
`meta.api = false`，无需自备 API/Key。**不要把真实账号的密钥粘贴到任何在线工具里。**

## 示例

输入（RFC 4226 示例密钥 + 计数器 0）：

```text
GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ
```

输出（6 位 / SHA1）：

```text
755224

6 位｜计数器 0｜SHA1
```
