# 编码检测

检测文本编码。

## 用途

判断一段文本原本是什么编码，并把按错误编码读出来的乱码解回原文：常见于 UTF-8 被当成 Latin-1 / GBK 读出来的场景。

## 输入

| 字段   | 类型   | 约束              |
| ------ | ------ | ----------------- |
| `text` | string | 最大 100,000 字符 |

疑似乱码的文本。工具会把它按 Latin-1 还原成字节再交给识别器，因此**要求字符码位都在 U+0000–U+00FF 之间**。

## 输出

| 字段   | 类型   | 说明                                                                        |
| ------ | ------ | --------------------------------------------------------------------------- |
| `text` | string | 检测结果（编码 + 置信度）、字节数、候选列表，以及按首选编码重新解码的预览。 |

## 选项

| 选项      | 取值        | 默认 | 说明                           |
| --------- | ----------- | ---- | ------------------------------ |
| `topN`    | `3` / `5`   | `5`  | 候选列表显示几条               |
| `preview` | 勾选 / 取消 | 勾选 | 是否输出按检测编码解码后的预览 |

## 限制

- **样本越短越不准**：几十字节以内的样本经常判错，请尽量贴更长的文本
- 依赖 chardet；文档原列的是 jschardet，因其许可是 LGPL-2.1+（弱 copyleft）与本项目「只用宽松许可依赖」的约定冲突，故改用 MIT 的 chardet
- 只能处理「按单字节编码误读」的乱码：文本里出现码位大于 U+00FF 的字符时无法还原原始字节
- 预览用 TextDecoder 解码，UTF-32 之类浏览器未实现的编码不会给出预览
- 纯 7 位文本直接判 ASCII，不经过识别器
- 输入上限 100,000 字符

## 数据流向

**纯本地处理。** 输入内容仅在浏览器内存中处理，不发送任何网络请求，不写入服务端。
`meta.api = false`，无需自备 API/Key。

## 示例

输入：

```text
（点工具内「示例」可载入：一段 UTF-8 字节被当成 Latin-1 读出来的乱码，共 42 字节）
```

输出：

```text
检测结果：UTF-8（置信度 100）
字节数：42
候选：
  1. UTF-8  100
  2. windows-1252  77
  3. Shift_JIS  10
  4. Big5  10
  5. GB18030  10

按 UTF-8 解码：
中华人民共和国中华人民共和国
```
