# 文本加密

文本 AES 加密解密。

## 用途

用 AES-GCM 给一段文本加解密：口令经 PBKDF2 派生密钥，密文打包成 base64，可以贴进任何地方传走。

## 输入

| 字段       | 类型   | 约束                    |
| ---------- | ------ | ----------------------- |
| `text`     | string | 最大 100,000 字符       |
| `password` | string | 口令，最大 100,000 字符 |

正文 + 口令。加密模式填明文，解密模式填密文。

## 输出

| 字段   | 类型   | 说明                                 |
| ------ | ------ | ------------------------------------ |
| `text` | string | 加密输出 base64 密文；解密输出明文。 |

## 选项

| 选项   | 取值                  | 默认      | 说明        |
| ------ | --------------------- | --------- | ----------- |
| `mode` | `encrypt` / `decrypt` | `encrypt` | 加密 / 解密 |

## 限制

- **密文无法找回**：口令不保存、也不参与任何同步，忘了口令就没有任何恢复手段
- 算法是 AES-256-GCM + PBKDF2(SHA-256, 100,000 次迭代)，盐与 IV 每次随机，因此同一明文两次加密结果不同
- 依赖浏览器的 WebCrypto，需要 HTTPS 或 localhost；在不安全上下文下会直接报错
- 口令强度决定安全性：本工具不做任何口令强度校验，弱口令仍可被暴力破解
- 密文长度约为明文的 1.4 倍（base64 膨胀 + 28 字节盐与 IV）
- 输入上限 100,000 字符

## 数据流向

**不联网。** 加密与解密全部由浏览器的 WebCrypto 在本地完成：

- 口令只在内存里参与 PBKDF2 派生，**不写入 localStorage、不发送、不记录**
- 密文只出现在当前页面的输出框里，复制或下载由你手动触发
- 换设备解密需要同一个口令 + 同一段密文，两者缺一不可

## 示例

输入：

```text
这是一段需要加密的明文。
```

输出：

```text
（每次不同：盐与 IV 随机生成，形如 Qx3…== 的 base64 串）
```
