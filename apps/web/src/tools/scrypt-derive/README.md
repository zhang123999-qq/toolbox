# Scrypt

用 Scrypt 从口令派生密钥（**内置 RFC 7914 实现**）。

## 用途

把口令「拉伸」成固定长度的密钥材料。Scrypt 除了可调迭代成本，还要求**大量内存**，因此比 #97 PBKDF2 更能抵抗 GPU / ASIC 并行破解。它是存储用户口令、派生加密密钥的推荐算法之一。

## ⚠️ 关于实现方式

**WebCrypto 没有 Scrypt**（标准里只有 PBKDF2 与 HKDF），所以本工具**自带一份 RFC 7914 的实现**：

```text
scrypt(P, S, N, r, p, dkLen)
  B = PBKDF2-HMAC-SHA256(P, S, 1, p * 128 * r)   ← 用 WebCrypto 的 deriveBits
  对每个 p 分块做 ROMix（Salsa20/8 核心 + BlockMix）  ← 本工具自己实现
  return PBKDF2-HMAC-SHA256(P, B, 1, dkLen)        ← 用 WebCrypto 的 deriveBits
```

首尾两步的 PBKDF2 交给浏览器 WebCrypto，中间的 ROMix 是纯 JS 的 32 位运算实现。
实现已用 RFC 7914 §12 的三组标准向量逐字节验证（含 N=1024/r=8/p=16 与 N=16384/r=8/p=1）。

## 输入

| 字段   | 类型   | 约束              | 说明              |
| ------ | ------ | ----------------- | ----------------- |
| `text` | string | 最大 200,000 字符 | 口令              |
| `salt` | string | 附加输入框        | 盐，按 UTF-8 编码 |

盐走**独立的附加输入框**，**只在浏览器内存里使用**。

## 输出

| 字段   | 类型   | 说明                                     |
| ------ | ------ | ---------------------------------------- |
| `text` | string | 派生密钥的十六进制（默认）或 Base64 编码 |

## 选项

| 选项          | 取值                 | 默认 | 说明                                       |
| ------------- | -------------------- | ---- | ------------------------------------------ |
| `blocks`      | 1024 / 16384 / 65536 | 1024 | **N**，CPU/内存成本参数，**必须是 2 的幂** |
| `parallelism` | 1 / 2 / 4            | 1    | **p**，并行度，线性增加计算量              |
| `length`      | 32 / 64              | 32   | dkLen，输出字节数                          |
| `format`      | hex / base64         | hex  | 输出编码                                   |

块大小 **r 固定为 8**（RFC 7914 推荐值，也是各实现的默认值），因此内存占用为 `128 × r × N = 1024 × N` 字节：
N=1024 → 1 MiB，N=16384 → 16 MiB，N=65536 → 64 MiB。

## 参数怎么选

OWASP《Password Storage Cheat Sheet》给出 Scrypt 的最低推荐：**N=2^17（131072）、r=8、p=1**（约 128 MiB 内存）。
本工具的下拉上限是 N=65536（64 MiB），若需要更高的 N，请直接调用本工具的 `scrypt()` 实现或换用原生库。

⚠️ **参数必须与盐一起存进数据库**：换参数后同一口令会派生完全不同的结果，否则无法校验。

## 限制

- **必须使用随机盐**（推荐 16 字节随机值）；固定盐会让相同口令派生相同结果
- 计算很慢是设计目标，不是 bug：N=65536、p=4 在本机约需数秒（已实测约 2.8 秒），选大参数时请稍候
- 内存需求超过 256 MiB 会被直接拒绝，避免把浏览器标签页拖垮
- 这是纯 JS 实现，比原生/WASM 实现慢；追求性能请用 `argon2-browser` 或原生库
- 输入上限 200,000 字符

## 数据流向

**纯本地处理。** 口令与盐只在浏览器内存中参与派生，**不发起任何网络请求、不写入 localStorage、不上传服务端**。
`meta.api = false`，无需自备 API/Key。

## 示例

输入（口令）：

```text
password
```

盐：

```text
NaCl
```

输出（N=1024 / p=1 / 32 字节 / hex）：

```text
（64 位十六进制，每次一致）
```
