# Hex 编解码

文本与十六进制互转，支持空格 / 连字符 / `0x` 前缀。

## 用途

把文本编码成十六进制，便于查看二进制 / 字节级内容（排查乱码、确认编码、
对比协议报文）；反向则用于把抓包、日志、内存 dump 里的十六进制串还原成
人能读的文字。

## 输入

| 字段   | 类型   | 约束              |
| ------ | ------ | ----------------- |
| `text` | string | 最大 200,000 字符 |

编码时是任意文本（中英混排、emoji 均可）；解码时是十六进制串。

## 输出

| 字段   | 类型   | 说明                                 |
| ------ | ------ | ------------------------------------ |
| `text` | string | 编码后为十六进制串；解码后为原始文本 |

## 选项

| 选项        | 取值                         | 默认   | 说明                                                       |
| ----------- | ---------------------------- | ------ | ---------------------------------------------------------- |
| `direction` | encode / decode              | encode | 编码或解码                                                 |
| `separator` | none / space / hyphen / `0x` | space  | 字节间的连接写法：`6869` / `68 69` / `68-69` / `0x68 0x69` |
| `uppercase` | 布尔                         | 关     | 十六进制字母用大写（`E4B8AD`）还是小写（`e4b8ad`）         |

## 限制

- 编码按 **UTF-8** 把文本转成字节，因此一个中文字符是三个字节、一个 emoji 是四个字节
- 本工具处理**文本**。文件转十六进制需要文件输入能力，模板尚未支持
- 解码宽容度较高：空格、逗号、连字符会被忽略，`0x` 与 `\x` 前缀会被剥掉，
  大写小写都认——从代码或抓包结果里直接粘贴通常无需清理
- 解码要求结果必须是合法 UTF-8；纯二进制内容（如加密后的密文）无法还原为文本，
  会明确报错而不是输出乱码
- 奇数个十六进制字符无法按字节拆分，会报错

## 数据流向

**纯本地处理。** 输入内容仅在浏览器内存中处理，不发送任何网络请求，不写入服务端。
`meta.api = false`，无需自备 API/Key。

## 示例

输入：

```text
Hi 中
```

输出（encode / space）：

```text
48 69 20 e4 b8 ad
```
