# TOTP 生成

按时间生成动态验证码（TOTP，RFC 6238）——就是 Google Authenticator、GitHub 两步验证用的那种 6 位数字。

## 用途

拿到共享密钥后直接算出当前这 30 秒的验证码，用来核对服务端实现是否一致、
排查「验证码总是错误」（多半是密钥编码、位数、周期或时钟不一致）。

## 输入

| 字段   | 类型   | 约束              | 说明                                        |
| ------ | ------ | ----------------- | ------------------------------------------- |
| `text` | string | 最大 200,000 字符 | Base32 共享密钥（允许空格、小写）           |

## 输出

| 字段   | 类型   | 说明                                      |
| ------ | ------ | ----------------------------------------- |
| `text` | string | 验证码 + 一行参数说明与本轮剩余有效秒数    |

## 选项

| 选项        | 取值                        | 默认   | 说明                                   |
| ----------- | --------------------------- | ------ | -------------------------------------- |
| `digits`    | 6 / 8                       | 6      | 验证码位数                             |
| `period`    | 30 / 60                     | 30     | 时间步长（秒）                         |
| `algorithm` | SHA1 / SHA256 / SHA512      | SHA1   | HMAC 摘要；绝大多数服务用 SHA1         |

## 限制

- 用**你本机的时钟**计算：本机时间不准就会算出错误验证码（这也是「总是不对」的常见原因）
- 只支持 Base32 密钥；`otpauth://` URI 请先把里面的 `secret=` 值抠出来
- 不支持生成二维码或 `otpauth://` URI（见「OTP 二维码」工具）
- 验证码随时钟推进不断变化，因此**不能**用「两次结果相同」判断实现是否正确——
  单测靠注入固定时间戳对照 RFC 6238 的已知向量

## 数据流向

**纯本地处理。** 密钥只在浏览器内存里参与运算，不发送任何网络请求。
`meta.api = false`，无需自备 API/Key。**不要把真实账号的密钥粘贴到任何在线工具里。**

## 示例

输入（RFC 6238 示例密钥的 Base32 形式）：

```text
JBSWY3DPEHPK3PXP
```

输出（6 位 / 30 秒 / SHA1，随时间变化）：

```text
324550

6 位｜周期 30 秒｜SHA1｜本轮还剩 12 秒
```
