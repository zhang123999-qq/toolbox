# Quoted-Printable

RFC 2045 邮件正文编码，按行折行并转义不可打印字节。

## 用途

把含中文或不可见字符的正文编码成可安全放进邮件的 ASCII 形式（`Content-Transfer-Encoding: quoted-printable`），
或把收到的 `=E4=B8=AD` 这类内容还原成原文。
用于调试邮件源、核对邮件客户端显示乱码的原因、构造符合 RFC 的测试邮件。

## 输入

| 字段   | 类型   | 约束              |
| ------ | ------ | ----------------- |
| `text` | string | 最大 200,000 字符 |

- 编码方向：任意文本（中英混排、emoji、多行均可）
- 解码方向：Quoted-Printable 正文片段（可含软换行）

## 输出

| 字段   | 类型   | 说明                                   |
| ------ | ------ | -------------------------------------- |
| `text` | string | 编码方向输出 QP 文本；解码方向输出原文 |

## 选项

| 选项        | 取值            | 默认   | 说明                                         |
| ----------- | --------------- | ------ | -------------------------------------------- |
| `direction` | encode / decode | encode | 编码或解码                                   |
| `length`    | 8–76 的整数     | 76     | 编码时每行的最大字符数（RFC 2045 上限为 76） |

## 限制

- 编码**只转义必要的字节**：可打印 ASCII（`!` 到 `~`，`=` 除外）原样保留，所以 `Hello World` 编码后不变
- 行尾的空格与制表符一定转义成 `=20` / `=09`，否则会被邮件网关悄悄吃掉
- 输出的换行统一是 CRLF（RFC 要求）；解码时 CRLF 会归一成 LF，便于与输入框里的文本直接比对
- 编码按行处理，所以「软换行」绝不会出现在词中间
- 解码要求还原结果是合法 UTF-8，否则明确报错而不是输出乱码
- 每行长度非法（非整数、超出 8–76）时直接报错，不会静默取默认值

## 数据流向

**纯本地处理。** 输入内容仅在浏览器内存中处理，不发送任何网络请求，不写入服务端。
`meta.api = false`，无需自备 API/Key。

## 示例

输入（默认选项：encode，每行 76）：

```text
中
```

输出：

```text
=E4=B8=AD
```

其他实算结果：

| 输入          | 选项        | 输出                               |
| ------------- | ----------- | ---------------------------------- |
| `Hello World` | encode / 76 | `Hello World`                      |
| `Hello `      | encode / 76 | `Hello=20`（行尾空格被转义）       |
| `é`           | encode / 76 | `=C3=A9`                           |
| 100 个 `A`    | encode / 76 | 75 个 `A` + `=` + CRLF + 25 个 `A` |
| `=E4=B8=AD`   | decode      | `中`                               |
