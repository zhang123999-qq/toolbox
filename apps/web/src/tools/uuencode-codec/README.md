# UUencode 编解码

经典 UUencode / UUDecode，输出带 `begin` / `end` 包裹。

## 用途

把二进制内容编码成只用可打印 ASCII 字符表示的文本，方便塞进邮件正文、Usenet 帖子或纯文本工单；
也可以把收到的 `begin 644 …` / `end` 段落还原成原文。
今天更多是调试老系统、解析历史归档、给只收纯文本的通道传文件时会用到。

## 输入

| 字段   | 类型   | 约束              |
| ------ | ------ | ----------------- |
| `text` | string | 最大 200,000 字符 |

编码时是任意文本（中英混排、emoji 均可）；解码时是 UUencode 文本。

## 输出

| 字段   | 类型   | 说明                                                       |
| ------ | ------ | ---------------------------------------------------------- |
| `text` | string | 编码后为 `begin` / `end` 包裹的 UUencode；解码后为原始文本 |

编码结果固定三段结构：

```text
begin 644 <文件名>
<数据行…>
end
```

每行最多 45 字节，行首第一个字符是「本行字节数 + 0x20」（45 字节 → `M`），
随后按 3 字节 → 4 字符映射到 `0x20..0x5F`。

## 选项

| 选项        | 取值            | 默认       | 说明                                                   |
| ----------- | --------------- | ---------- | ------------------------------------------------------ |
| `direction` | encode / decode | encode     | 编码或解码                                             |
| `prefix`    | 文本            | `data.txt` | 只作用于编码：`begin` 行里的文件名，空白会被换成下划线 |

## 限制

- 只处理**文本**。编码走 UTF-8 字节，解码要求结果是合法 UTF-8；二进制内容会明确报错而不是输出乱码
- 只实现 `644` 权限位；`begin` 行的权限位在解码时被忽略
- 编码采用 `0x20..0x5F` 的朴素映射（不做历史实现里「值为 0 时改写为 backtick」的替换），
  因此数据行里可能出现空格。空格是有效数据，**复制时不要去掉行尾空格**；
  解码侧同时兼容 backtick 写法，能直接吃老工具产出的文件
- 解码容忍缺失 `begin` / `end` 包裹行，也容忍经典的零长度终止行（单个 backtick 或空行）
- 输入上限 200,000 字符

## 数据流向

**纯本地处理。** 输入内容仅在浏览器内存中处理，不发送任何网络请求，不写入服务端。
`meta.api = false`，无需自备 API/Key。

## 示例

输入：

```text
Hello, World!
```

输出（encode，`prefix = data.txt`）：

```text
begin 644 data.txt
-2&5L;&\L(%=O<FQD(0
end
```

反向解码 `#0V%T` 得到 `Cat`（缺 `begin` / `end` 也能解）。
