# OAuth 流程

OAuth 2.0 三种常见授权流程的步骤说明、示例 URL 与参数表，快速对照实现。

## 用途

接入第三方登录 / 开放平台时，翻 RFC 太慢。本工具按你选的流程给出「第一步跳哪、第二步换什么参数、
哪些参数必须校验」的速查清单。

## 输入

| 字段   | 类型   | 约束                      |
| ------ | ------ | ------------------------- |
| `text` | string | 触发用，最大 200,000 字符 |

## 选项

| 选项     | 取值                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------ |
| 授权流程 | `authorization-code`（授权码，推荐）/ `implicit`（隐式，已不推荐）/ `client-credentials`（客户端凭证） |

## 三种流程怎么选

| 流程            | 谁用                       | 有没有用户 | client_secret 在哪  |
| --------------- | -------------------------- | ---------- | ------------------- |
| 授权码（+PKCE） | Web / 移动 / SPA           | 有         | 后端（SPA 用 PKCE） |
| 隐式            | 旧 SPA（OAuth 2.1 已弃用） | 有         | 无                  |
| 客户端凭证      | 服务对服务                 | 无         | 后端                |

## 安全要点

- **state 必校验**：防 CSRF，回调时原样比对
- **redirect_uri 精确匹配**：协议、域名、端口、路径都要和注册一致
- **client_secret 不下发前端**：只能待在后端
- **公共客户端用 PKCE**：SPA / 移动端没有后端保密能力，必须上 code_challenge
- 隐式流程不要再用，迁移到授权码 + PKCE

## 数据流向

**纯本地处理。** 不发起真实 OAuth 请求，只输出说明文本。`meta.api = false`。
