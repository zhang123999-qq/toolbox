# Favicon 检查

检查站点的 favicon 是否声明完整、地址是否可访问：解析页面 `<link>`
图标声明并逐个发 HEAD 请求验证，附带默认 `/favicon.ico` 兜底检查。

## 用途

- 上线前确认站点图标链路：`<link rel="icon">`、`apple-touch-icon` 是否存在、地址能否打开
- 快速定位图标 404 / 跨域拦截 / 声明缺失问题

## 输入

| 字段   | 类型   | 约束                                                  |
| ------ | ------ | ----------------------------------------------------- |
| `text` | string | 站点 URL（必须 `http(s)://` 开头），最大 200,000 字符 |

## 选项

| 选项      | 类型   | 说明                                                                         |
| --------- | ------ | ---------------------------------------------------------------------------- |
| 页面 HTML | string | 可选粘贴该页面的 HTML 源码，用于解析 `<link>` 图标声明；留空则只检查默认地址 |

## 检查逻辑

1. **声明解析**：纯正则提取 `<link>` 标签，`rel` 含 `icon`（`icon` /
   `shortcut icon` / `apple-touch-icon` / `apple-touch-icon-precomposed` /
   `mask-icon`，大小写不敏感）即收录；`href` 相对站点 URL 解析为绝对地址
   （解析失败或非 `http(s)` 跳过），保留 `sizes` / `type`
2. **默认地址**：站点根目录的 `/favicon.ico`（已在声明中出现则去重，不重复检查）
3. **可达性检查**：对每个候选地址先发 HEAD 请求（15 秒超时），返回 405 / 501
   时回退 GET；状态码 2xx 视为可访问；网络异常 / 超时记为失败但不中断其他候选

## 输出

- 结果表格：地址 / 来源（声明的 `rel`+`sizes` / 默认地址）/ 状态码 /
  Content-Type / 结果（OK / 失败）/ 备注
- 建议区：无声明时建议添加；缺 `apple-touch-icon` 时建议补充 180×180；
  有失败项时提示结合声明清单人工确认
- 复制 / 下载：同一份纯文本报告

## 限制说明

- **跨域误报**：检查在浏览器内直接向目标站点发 HEAD 请求，若目标站点未配置
  CORS，浏览器会拦截响应，报告中如实标注为失败——这不一定是图标真的不可用，
  请结合上方的声明清单人工判断
- 正则解析 HTML 是启发式的：注释里的 `<link>`、JS 动态注入的声明可能被
  误收录或漏掉；`sizes` 为空字符串时视为未声明
- 只检查地址可达性与响应头，不下载验证图片内容是否合法

## 数据流向

**浏览器发起 fetch（D 类）。** HEAD / GET 请求直接发往被检查的站点，
不经过本工具后端。`meta.api = false`（无 Key、无自有接口）。
