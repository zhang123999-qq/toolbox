# XML 格式化

XML 美化缩进与压缩成单行，并校验是否良构。

## 用途

把压缩在一行、或缩进混乱的 XML 重排成可读的层级结构；也可反向去掉排版空白以减小体积。
解析失败时给出「第 N 行第 M 列」的中文提示，便于直接跳到出错位置。

## 输入

| 字段   | 类型   | 约束                |
| ------ | ------ | ------------------- |
| `text` | string | 最大 2,000,000 字符 |

## 输出

| 字段   | 类型   | 说明                                  |
| ------ | ------ | ------------------------------------- |
| `text` | string | 格式化 / 压缩后的 XML；空输入返回空串 |

## 选项

| 选项     | 取值                | 默认     | 说明                         |
| -------- | ------------------- | -------- | ---------------------------- |
| `mode`   | `format` / `minify` | `format` | 美化缩进 / 压缩成单行        |
| `indent` | `2` / `4` / `tab`   | `2`      | 缩进档位（仅 `format` 生效） |

## 实现说明：为什么没有直接用 DOMParser

浏览器原生 `DOMParser` + `XMLSerializer` 确实能解析 XML，但本工具的 `utils.ts` 必须在
**node（单测）与 jsdom（组件测试）两个环境下给出完全一致的结果**，而原生解析器做不到：

- node 环境根本没有 `DOMParser`；
- 各实现的报错既没有行列号，严格程度也不一致（例如未声明的命名空间前缀）。

因此结构解析、错误定位与输出一律走自研的递归下降解析器；`DOMParser` 只在存在时
（`hasNativeParser()`）额外做一次良构校验，作为第二道闸门。

## 限制

- 输入上限 2,000,000 字符，超出抛出 `XmlFormatterError`
- 只支持 XML 1.0 的良构子集：不解析 DTD 内部子集的实体声明，不校验 Schema
- 格式化会丢弃标签之间的纯空白文本节点（`<a>   </a>` → `<a/>`）
- 属性值按 XML 规范转义（`"` 与换行分别转成 `&quot;` / `&#10;`）
- 只识别 XML 预定义的 5 个实体（`&lt;` `&gt;` `&amp;` `&quot;` `&apos;`）与数字字符引用，
  其余实体视为非法

## 数据流向

**纯本地处理。** 输入内容仅在浏览器内存中处理，不发送任何网络请求，不写入服务端。
`meta.api = false`，无需自备 API/Key。

## 示例

输入：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<catalog><book id="1"><title>工具库</title><price>29.9</price></book></catalog>
```

输出（`mode=format`、`indent=2`）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<catalog>
  <book id="1">
    <title>工具库</title>
    <price>29.9</price>
  </book>
</catalog>
```
