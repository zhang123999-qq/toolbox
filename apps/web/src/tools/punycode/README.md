# Punycode

国际化域名（IDN）编码解码，按 RFC 3492 逐标签处理。

## 用途

把中文、日文、俄文等非 ASCII 域名转成 DNS 能承载的 `xn--` 形式（ACE 编码），
或反过来把 `xn--fiqs8s` 这类看起来像乱码的域名还原成可读文字。
用于核对域名是否等价、排查「浏览器地址栏显示中文、抓包里全是 xn--」的对应关系、识别同形异义域名。

## 输入

| 字段   | 类型   | 约束              |
| ------ | ------ | ----------------- |
| `text` | string | 最大 200,000 字符 |

编码方向输入 Unicode 域名（`中国.中国`）；解码方向输入 ACE 域名（`xn--fiqs8s.xn--fiqs8s`）。
按 `.` 逐标签处理：不含非 ASCII 的标签原样保留。

## 输出

| 字段   | 类型   | 说明                                                |
| ------ | ------ | --------------------------------------------------- |
| `text` | string | 编码方向输出 `xn--` 域名；解码方向输出 Unicode 域名 |

## 选项

| 选项        | 取值            | 默认   | 说明       |
| ----------- | --------------- | ------ | ---------- |
| `direction` | encode / decode | encode | 编码或解码 |

Punycode 的算法参数（base / tmin / tmax / skew / damp…）由 RFC 3492 固定，没有可调项，故只有方向一个选项。

## 限制

- **算法为本仓自实现**（RFC 3492 §6.3），不依赖 Node 的 `punycode`（已废弃且在浏览器里不存在），也不借 `URL.hostname`（Node 与浏览器行为不一致）
- 只做标签级编解码，不做 IDNA2008 的完整映射（大小写折叠、NFC 归一化、禁用码点校验等由上层注册/浏览器负责）
- 解码方向要求输入至少有一个 `xn--` 标签，否则明确报错；`xn--` 前缀大小写不敏感
- 非法 Punycode（含字母表外字符、数字中途截断、解出码点越界）一律报错，不会产出乱码

## 数据流向

**纯本地处理。** 输入内容仅在浏览器内存中处理，不发送任何网络请求，不写入服务端。
`meta.api = false`，无需自备 API/Key。

## 示例

输入：

```text
中国.中国
```

输出：

```text
xn--fiqs8s.xn--fiqs8s
```

其他实算结果（样例取自 RFC 3492 §7.1，输出为域名级的 `xn--` 形式）：

| 输入                     | 选项   | 输出                                 |
| ------------------------ | ------ | ------------------------------------ |
| `中国`                   | encode | `xn--fiqs8s`                         |
| `他们为什么不说中文`     | encode | `xn--ihqwcrb4cv8a8dqg056pqjye`       |
| `Pročprostěnemluvíčesky` | encode | `xn--Proprostnemluvesky-uyb24dma41a` |
| `中国.com`               | encode | `xn--fiqs8s.com`                     |
| `xn--fiqs8s.xn--fiqs8s`  | decode | `中国.中国`                          |
| `example.com`            | encode | `example.com`（纯 ASCII 原样输出）   |
