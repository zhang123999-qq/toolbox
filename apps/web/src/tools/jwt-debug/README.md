# JWT 调试

解码 JWT（JWS）的 Header 与 Payload，解释 `exp` / `iat` / `nbf` 等时间声明，
并在填入密钥时用 jose 校验签名。

## 用途

拿到一个 token 想确认它到底签发了谁、什么时候过期、签名对不对时用。
本工具区分「只读解码」与「验签」：不填密钥也能看清 payload（但 payload 任何人都能伪造），
填了密钥才会真正校验签名。

## 输入

| 字段   | 类型   | 约束                                                 |
| ------ | ------ | ---------------------------------------------------- |
| `text` | string | 一段 compact JWT（`aaa.bbb.ccc`），最大 200,000 字符 |

## 选项

| 选项        | 说明                                                        |
| ----------- | ----------------------------------------------------------- |
| 密钥/口令   | HMAC 共享密钥，验 HS256/HS384/HS512 用                      |
| 公钥（PEM） | `-----BEGIN PUBLIC KEY-----`，验 RS256/RS384/RS512/ES256 用 |

两者留其一即可；都不填则只解码不验签。

## 输出

```text
## Header
{ "alg": "HS256", "typ": "JWT" }

## Payload
{ "sub": "1234567890", "name": "...", "iat": 1516239021, "exp": 9999999999 }

## 声明解读
签发时间（iat）：2018-01-18T01:30:21.000Z
过期时间（exp）：...
状态：未过期，还剩 ... 秒
sub：1234567890

## 验签
验签通过：签名有效（alg=HS256）
```

## 说明

- **JWE（5 段）** 是加密令牌，无法直接读明文，本工具会提示
- 验签失败会给出 jose 错误码，常见：`ERR_JWT_EXPIRED`（已过期）、`ERR_JWS_SIGNATURE_VERIFICATION_FAILED`（签名不对）
- 验签需要 WebCrypto（HTTPS 或 localhost）

## 数据流向

**纯本地处理。** 解码与验签都在浏览器内完成，token 不上传。`meta.api = false`。
