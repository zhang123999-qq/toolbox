# 移动友好检测

分析网页 HTML 的移动友好度：viewport、媒体查询、固定像素宽度、表格布局，
0–100 打分并逐项给改进建议。

## 用途

页面在手机上错位、横向滚动、字小点不动时，先拿源码跑一遍，快速定位问题。

## 输入

| 字段   | 类型   | 约束                                            |
| ------ | ------ | ----------------------------------------------- |
| `text` | string | 粘贴分析模式下为 HTML；实时抓取模式下为页面 URL |

## 选项

| 选项     | 取值                    |
| -------- | ----------------------- |
| 分析模式 | `粘贴分析` / `实时抓取` |

## 输出

```text
来源：粘贴的 HTML
移动友好得分：65 / 100
结论：移动体验较差：存在影响小屏浏览的问题，建议按 findings 逐项整改

[问题] viewport：未找到 <meta name="viewport">，移动端会按桌面宽度渲染
  建议：在 <head> 添加 <meta name="viewport" content="width=device-width, initial-scale=1">
[建议] 媒体查询：未检测到 @media
  建议：用 @media 媒体查询为小屏写一套布局，避免桌面布局直接压缩
[通过] 固定宽度：未发现 ≥100px 的固定像素宽度
[通过] 表格布局：未使用 <table> 布局
```

## 评分规则

- 问题项每项 −25（缺 viewport / 固定像素宽度 ≥100px）
- 建议项每项 −10（无媒体查询 / 含 table 布局）
- ≥90 移动友好，70–89 基本可用，<70 建议逐项整改

## 浏览器边界说明

- **实时抓取需目标站点允许跨域（CORS）**，否则浏览器直接拦截请求；
  失败时请改用「粘贴分析」（在目标页面右键「查看网页源代码」复制）
- 纯静态分析：不渲染页面，看不到 JS 动态生成的 DOM 与真实渲染效果，
  触控目标尺寸等需真机验证的项不在范围内

## 限制

- 只分析给定的 HTML 文本，不加载 CSS / JS 外链
- 结论是启发式的，不能替代 Google Mobile-Friendly Test 等真机渲染检测

## 数据流向

**浏览器发起 fetch（D 类，仅实时抓取模式）。** 粘贴分析模式纯本地计算；
抓取模式请求直连目标站点，不经过本工具后端。`meta.api = true`。
