# Base85 编解码

ASCII85 与 Z85 编解码，比 Base64 更紧凑。

## 用途

Base85 用 85 个可打印字符表示二进制，**每 4 字节只占 5 个字符**（Base64 要 8 个），
体积比 Base64 小约 25%。Adobe PostScript/PDF 用 ASCII85，ZeroMQ 用 Z85，
Git 的二进制 diff 也用类似编码。

## 输入

| 字段   | 类型   | 约束              |
| ------ | ------ | ----------------- |
| `text` | string | 最大 200,000 字符 |

## 输出

| 字段   | 类型   | 说明                          |
| ------ | ------ | ----------------------------- |
| `text` | string | 编码后为 Base85；解码后为原文 |

## 选项

| 选项        | 取值            | 默认    | 说明                             |
| ----------- | --------------- | ------- | -------------------------------- |
| `direction` | encode / decode | encode  | 编码或解码                       |
| `mode`      | ascii85 / z85   | ascii85 | ASCII85（Adobe）或 Z85（ZeroMQ） |

## 限制

- **ASCII85**：字母表从 `!`（33）起连续 85 个字符；支持 `z` 缩写（代表 4 个零字节）与
  `<~ … ~>` 包裹形式，末组不足 4 字节时按实际长度输出
- **Z85**：字母表由 ZeroMQ 规范固定；要求 4 字节对齐，编码时不足会**补零字节**，
  因此解码结果末尾可能带出填充用的零字节（这是 Z85 本身不定义 padding 导致的）
- 解码要求结果必须是合法 UTF-8；纯二进制内容无法还原为文本，会明确报错

## 数据流向

**纯本地处理。** 输入内容仅在浏览器内存中处理，不发送任何网络请求，不写入服务端。
`meta.api = false`，无需自备 API/Key。

## 示例

输入：

```text
Man
```

输出（ascii85 / encode）：

```text
9jqo^
```
