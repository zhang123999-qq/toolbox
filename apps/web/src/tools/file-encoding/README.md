# 文件编码检测

上传文件，检测其文本编码（chardet），并按该编码解码预览内容。

## 用途

从 Windows 传来的 CSV / 日志 / 小说 txt 打开是乱码时，先拿它检测到底是 GBK、UTF-8 还是别的编码，再决定怎么转码。

## 与 charset-detect 的区别

`charset-detect`（#40）是粘贴一段乱码文本做检测；本工具**只走文件上传**，直接读文件的原始字节（取前 1 MiB 做样本），检测完还能按该编码把整个文件解码出来预览。

## 输入

| 字段   | 类型 | 约束      | 说明                 |
| ------ | ---- | --------- | -------------------- |
| `file` | File | ≤ 200 MiB | 文本文件，**不上传** |

## 输出

| 字段   | 类型   | 说明                                          |
| ------ | ------ | --------------------------------------------- |
| `text` | string | 检测报告：最佳编码 + 置信度 + 候选 + 解码预览 |

```text
文件：gb.txt（4 字节）
检测结果：GB18030（置信度 95）
候选：
  1. GB18030  95
  2. windows-1252  10

按 GB18030 解码预览：
你好
```

## 选项

| 选项      | 取值    | 默认 | 说明             |
| --------- | ------- | ---- | ---------------- |
| `topN`    | 1–10    | 3    | 展示几个候选编码 |
| `preview` | boolean | true | 是否给出解码预览 |

## 限制

- **空文件直接报错**；**超过 200 MiB 直接报错**
- 纯 7 位字节走快速路径直接判 ASCII（chardet 对短 ASCII 样本会给出奇怪的高分候选）
- UTF-8 BOM 头直接判 UTF-8
- 预览最多 5000 字符，超长截断并标注
- 当前环境不支持的编码（如 UTF-32）会中文提示无法预览
- 检测走 `chardet`（analyse / detect），全程本地

## 数据流向

**纯本地处理。** 文件只读进浏览器内存检测，`meta.api = false`，无需自备 API/Key。
