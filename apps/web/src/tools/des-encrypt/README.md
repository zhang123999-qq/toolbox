# DES 加密

DES / 3DES 加密解密，**仅用于兼容遗留系统**。

## ⚠️ 安全警告（务必先读）

- **DES 的 56 位密钥已可被暴力破解**：1998 年 EFF 的 Deep Crack 用不到 3 天破解；如今专用硬件/云算力只需数小时甚至更短。**DES 不具备任何现代意义上的安全性。**
- **3DES（Triple DES）也已弃用**：NIST 已于 2017 年将其标记为「不再批准用于新用途」，并计划在 2023 年后彻底停用；它的 64 位分组还会带来生日攻击（Sweet32）风险。
- 本工具存在的**唯一理由**是：对接仍在用 DES/3DES 的遗留系统、老式硬件协议或历史数据。
- 新系统请改用 **#90 AES 加密**（优先 AES-GCM）。本工具不应用于保护任何新的敏感数据。

## 用途

对文本做 DES / 3DES 加解密，支持 CBC 与 ECB 两种模式，兼容 OpenSSL 风格的六种填充。

## 输入

| 字段   | 类型   | 约束              | 说明                          |
| ------ | ------ | ----------------- | ----------------------------- |
| `text` | string | 最大 200,000 字符 | 加密时是明文，解密时是密文    |
| `key`  | string | 附加输入框        | DES 8 字节 / 3DES 24 字节     |
| `iv`   | string | 附加输入框        | CBC 必填且为 8 字节；ECB 忽略 |

密钥与 IV 走**独立的附加输入框**（不放进选项下拉），并且**只在浏览器内存里使用**。

## 输出

| 字段   | 类型   | 说明                                                           |
| ------ | ------ | -------------------------------------------------------------- |
| `text` | string | CBC：`<iv(base64)>.<密文(base64)>`；ECB：只有 `<密文(base64)>` |

## 选项

| 选项        | 取值                | 默认    | 说明                                                     |
| ----------- | ------------------- | ------- | -------------------------------------------------------- |
| `method`    | des / 3des          | des     | 单 DES 或三重 DES                                        |
| `mode`      | CBC / ECB           | CBC     | **建议 CBC**；ECB 相同明文块产出相同密文块，泄漏结构信息 |
| `direction` | encrypt / decrypt   | encrypt | 加密或解密                                               |
| `encoding`  | utf8 / hex / base64 | utf8    | 密钥（与 IV 输入框）的字符串表示方式                     |
| `padding`   | pkcs7 / zero / none | pkcs7   | 填充方式；`none` 要求明文长度是 8 的整数倍               |

## 限制

- 输出密文**不含完整性校验**（没有 MAC/AEAD），密文被篡改时解密不会自动报错 —— CBC/ECB 都不提供认证
- `zero` 填充在解密时会丢弃结尾的 `\0`，明文本身以 `\0` 结尾时无法还原
- 3DES 只接受 24 字节（三密钥）密钥；16 字节的双密钥变体需要时再补
- 密钥/IV 填错时解密结果可能是乱码，本工具会尽量报「不是合法 UTF-8」而不是输出乱码

## 数据流向

**纯本地处理。** 明文、密钥、IV 全部只在浏览器内存中流转：加密与解密由页面内的 `crypto-js` 完成，
**不发起任何网络请求、不写入 localStorage、密钥与明文绝不上传**。
`meta.api = false`，无需自备 API/Key。

## 示例

输入（默认 des / CBC / pkcs7 / utf8）：

```text
这是一段需要加密的明文。
```

密钥：

```text
deskey01
```

IV：

```text
ivvector
```

输出：

```text
<iv 的 base64>.<密文的 base64>
```
