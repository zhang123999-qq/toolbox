# 提交信息生成

按 Conventional Commits（约定式提交）规范，本地拼出一条 commit message，不调用 LLM。

## 输入

| 字段   | 类型   | 约束              |
| ------ | ------ | ----------------- |
| `text` | string | 最大 200,000 字符 |

输入框只作触发用，留空不产出。

## 选项

| 选项 key      | 界面标签       | 取值 / 说明                                                                      |
| ------------- | -------------- | -------------------------------------------------------------------------------- |
| `type`        | 提交类型       | feat / fix / docs / style / refactor / perf / test / chore / ci / build / revert |
| `scope`       | 影响范围       | 可选，如 `auth`、`checkout`，为空则省略括号                                      |
| `description` | 描述           | 一句话说明（必填，空则报错）                                                     |
| `body`        | 正文           | 多行，详细说明动机与取舍                                                         |
| `breaking`    | 包含不兼容变更 | 勾选后追加 `BREAKING CHANGE:` 段                                                 |
| `footer`      | 脚注           | 如 `Closes #123`、`Reviewed-by: ...`                                             |

## 输出

```text
feat(auth): 新增手机号登录

调用短信网关，支持验证码重发

BREAKING CHANGE: 本次提交包含不兼容的 API 变更

Closes #123
```

## 限制

- 不做语义分析，不自动改写英文时态；描述照填
- 不生成 issue 引用，footer 需手写

## 数据流向

**纯本地处理。** 纯字符串拼接。`meta.api = false`。
