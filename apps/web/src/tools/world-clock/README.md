# 世界时钟

并列展示多个 IANA 时区的当前墙上时间与 UTC 偏移，一眼看清「北京几点、纽约几点」。

## 用途

跨时区协作、排班、跨国会议时，需要同时盯住几个城市的当前时间。
本工具接收一组 IANA 时区名（每行一个），输出每个时区此刻的**墙上时间**与**相对 UTC 的偏移**，
夏令时（DST）由运行时的 `Intl` 自动处理，不需要自己维护偏移表。

## 输入

| 字段   | 类型   | 约束                                    |
| ------ | ------ | --------------------------------------- |
| `text` | string | 每行一个 IANA 时区名，最大 200,000 字符 |

空行与行首尾空白会被忽略。非法时区名（无法通过 `Intl.supportedValuesOf('timeZone')` 校验）会直接报错。

## 输出

| 字段   | 类型   | 说明                                   |
| ------ | ------ | -------------------------------------- |
| `text` | string | 每个时区一行，列对齐，附 `(UTC±HH:mm)` |

```text
Asia/Shanghai      2026-09-27 15:30:45  (UTC+08:00)
Europe/London      2026-09-27 08:30:45  (UTC+01:00)
America/New_York   2026-09-27 03:30:45  (UTC-04:00)
```

## 选项映射

| 选项 key | 界面标签  | 语义                                               |
| -------- | --------- | -------------------------------------------------- |
| `hour12` | 12 小时制 | 开启后用 12 小时制并标注 上午/下午；默认 24 小时制 |

## 实现规则 / 算法

1. **时区校验**：优先读取 `Intl.supportedValuesOf('timeZone')` 白名单；运行时不提供该 API 时，
   退化为尝试 `new Intl.DateTimeFormat('en-US', { timeZone })`，非法名会抛 `RangeError`，据此判定。
2. **墙上时间**：`Intl.DateTimeFormat#formatToParts` 直接取出该时区的 年/月/日/时/分/秒。
3. **UTC 偏移**：把目标时区的墙上时间当作 UTC 构造一个 `Date`，它与真实时刻的毫秒差除以 60000，
   即该时区此刻相对 UTC 的分钟偏移。这个做法天然覆盖夏令时——Intl 在不同日期给出不同墙上时间，
   差出来的偏移也就自动不同。
4. 全程不手写任何偏移表、不硬编码 DST 起止日期。

## 浏览器 / 运行时边界

- 时区数据来自浏览器 / Node 自带的 ICU；旧版浏览器可能缺少数十年后的 DST 规则，属运行时数据问题，非本工具缺陷。
- `Intl.supportedValuesOf` 在非常老的环境不存在，已做退化校验。
- 「当前时间」取调用瞬间的系统时钟；刷新或重算都会更新，输出不做缓存。
- 时区名区分大小写，且必须是 IANA 名（`Asia/Shanghai`），不接受 `CST`、`GMT+8` 这类缩写。

## 示例

输入：

```text
Asia/Shanghai
Europe/London
America/New_York
```

输出（随当前时刻变化）：

```text
Asia/Shanghai      2026-09-27 15:30:45  (UTC+08:00)
Europe/London      2026-09-27 08:30:45  (UTC+01:00)
America/New_York   2026-09-27 03:30:45  (UTC-04:00)
```
