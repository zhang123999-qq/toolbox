# 死链检查

批量检测 URL 列表的存活状态（每行一个，最多 200 行）：逐个发送 HEAD
请求（405/501 时自动回退 GET），并发 5 个，输出存活 / 重定向 / 死链 /
超时 / 错误 / 无效统计、死链清单与存活率，支持复制 / 导出报告。

与「链接检查」（#659）的区别：本工具直接检测给定的 URL 列表，
不做页面 HTML 的链接提取。

## 输入

| 字段   | 类型   | 约束                            |
| ------ | ------ | ------------------------------- |
| `text` | string | URL 列表，每行一个，最多 200 行 |

## 选项

无。

## 输出示例

```text
共 3 个 URL：存活 1　重定向 0　死链 1　超时 0　错误 0　无效 1　存活率 33%

格式无效（未检测）：
  not a url（第 3 行：URL 格式不正确）

死链清单：
  [死链] https://example.com/404-page（HTTP 404）
```

## 浏览器边界说明

- 用浏览器 `fetch` 直连目标站点：目标须允许跨域（返回 CORS 头）或与本站同源；
  被拦截的记为「错误」并注明原因，**不编造成「死链」**
- 超时 15 秒；并发 5 个；只检测 HTTP 层可达性，不执行 JS

## 限制

- 每行必须是 `http(s)` 开头的完整 URL；相对地址、mailto: 等会被标记为「无效」
- 需要登录态或反爬的站点可能被误判为死链 / 错误

## 数据流向

**浏览器发起 fetch（D 类）。** 请求直连目标站点，不经过本工具后端。`meta.api = true`
（浏览器直连外部站点）。
