# BigJSON 流式（受限实现）

对大 JSON 做**单遍扫描**：规模统计、键路径抽样、第一个语法错误的行列定位。

## 用途

拿到一份几十 MB 的接口 dump / 导出文件时，`JSON.parse` 要么爆内存要么半天没反应。
先用本工具扫一遍：它多大、都有哪些路径、有没有语法错误——再决定要不要全量解析、
要不要先清洗。

## 为什么是「受限实现」

规划表原定走 Node 的 `stream` 与其上的流式 JSON parser。**浏览器里两者都不可用，
且本项目禁止新增 npm 依赖**，因此本工具降级为自研**单遍字符扫描**：

- ❌ 不把 JSON 物化成对象树（那是 `json-formatter` / `json-tree` 的活）
- ❌ 不支持取值、过滤、按路径导出——那是先清洗后交给别的工具
- ❌ 不做增量 / 断点续扫，一次粘贴一次扫完
- ✅ 常数内存（只留路径取样与容器栈），线性时间，遇到第一处错误即停

## 输入

| 字段   | 类型   | 约束                |
| ------ | ------ | ------------------- |
| `text` | string | 最大 8,000,000 字符 |

## 输出

| 字段   | 类型   | 说明                         |
| ------ | ------ | ---------------------------- |
| `text` | string | 依 mode 而定；空输入返回空串 |

### `mode = stats`

```
字符数：46
行数：4
对象数：1
数组数：1
键值对数：3
字符串值：3
数字值：1
布尔值：0
null 值：0
最大嵌套深度：2
结构闭合：是
```

语法有问题时追加一行：`注意：第 X 行第 Y 列起有语法问题，以上统计可能不完整`。

### `mode = paths`

```
键路径抽样（首次出现顺序，最多 25 条）
$
$.name
$.tags
$.tags[0]
$.tags[1]
$.n
```

超过取样上限后追加 `另有 N 次新路径未被收录（已达取样上限）`。

### `mode = error`

```
第 2 行第 13 列：出现了多余的逗号（不允许尾随逗号）
  行内容："a": [1,]
```

没有问题时输出 `未发现语法错误（结构完全闭合，最深嵌套 N 层）`。

## 选项

| 选项   | 取值                          | 默认    | 说明                       |
| ------ | ----------------------------- | ------- | -------------------------- |
| `mode` | `stats` \| `paths` \| `error` | `stats` | 统计 / 路径抽样 / 错误定位 |
| `topN` | `10` \| `25` \| `50`          | `25`    | 路径抽样条数上限           |

## 限制

- 输入上限 8,000,000 字符，超过抛 `BigJsonError`
- **只报第一处语法错误**：后续位置大概率是连带错位，报一堆反而误导
- 路径取样满了之后不再收录新路径，也无法判断「到底有多少条不同路径」
- 扫描器覆盖标准 JSON 的常见错误（尾随逗号、缺引号、控制字符、非法标识符、
  括号不匹配、键后缺冒号、成员间缺逗号等），但**不等价于完整解析器**：
  通过本工具的 `error` 模式不代表 `JSON.parse` 一定通过，反之亦可
- 不算数是类的极少数场景（如 surrogate pair 边界）可能被放行

## 数据流向

**纯本地处理。** 输入内容仅在浏览器内存中处理，不发送任何网络请求，不写入服务端。
`meta.api = false`，无需自备 API/Key。

## 示例

输入：

```json
{
  "name": "工具库",
  "metrics": { "tools": 870, "stars": [12, 34] },
  "tags": ["json", "static"]
}
```

输出（`mode = stats`）：

```
字符数：92
行数：4
对象数：2
数组数：2
键值对数：4
字符串值：3
数字值：3
布尔值：0
null 值：0
最大嵌套深度：2
结构闭合：是
```
