# 文本合并

三方合并，解决冲突。

## 用途

把「基准版本 + 我的改动 + 他人的改动」合成一份：两侧改在不同行时自动合并，改在同一行时标出冲突或按偏好取一方。

## 输入

| 字段    | 类型   | 约束                        |
| ------- | ------ | --------------------------- |
| `text`  | string | 最大 100,000 字符           |
| `textB` | string | 我的版本，最大 100,000 字符 |
| `textC` | string | 他人版本，最大 100,000 字符 |

三个输入框：基准版本（共同祖先）、我的版本、他人版本。三者是平级输入。

## 输出

| 字段   | 类型   | 说明                                                                                   |
| ------ | ------ | -------------------------------------------------------------------------------------- |
| `text` | string | 合并后的文本。有冲突时 auto 模式会插入冲突标记，mine / theirs 模式直接取一方并附说明。 |

## 选项

| 选项     | 取值                                                       | 默认   | 说明             |
| -------- | ---------------------------------------------------------- | ------ | ---------------- |
| `prefer` | `auto`（标冲突） / `mine`（取我的） / `theirs`（取他人的） | `auto` | 冲突时的处理偏好 |

## 限制

- 以**行**为最小单位：改动落在同一行即判冲突，不做行内细分（不是完整 diff3）
- 不保证处理相邻行的复杂重叠：两侧改动区间一旦咬合，就整段判冲突
- 冲突标记用 `<<<<<<< 我的版本` / `=======` / `>>>>>>> 他人版本`，与 git 约定一致
- 输出统一用 LF，输入里的 CRLF 会被规范化
- 不处理文件模式、重命名、二进制内容
- 输入上限 100,000 字符（每个框）

## 数据流向

**纯本地处理。** 输入内容仅在浏览器内存中处理，不发送任何网络请求，不写入服务端。
`meta.api = false`，无需自备 API/Key。

## 示例

输入：

```text
第一行
第二行
第三行
```

我的版本：

```text
第一行
第二行（我改的）
第三行
```

他人版本：

```text
第一行
第二行
第三行（他人加的）
```

输出：

```text
第一行
第二行（我改的）
第三行（他人加的）
```
