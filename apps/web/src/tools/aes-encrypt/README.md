# AES 加密

AES-GCM / AES-CBC 文本加密解密。

## 用途

把一段文本用口令之外的**密钥 + IV** 加密成可复制的密文串，或把密文还原。适合在本地临时保护一段文本、对接使用标准 AES 的接口、验证自己实现的加解密是否正确。

## 输入

| 字段   | 类型   | 约束              | 说明                                |
| ------ | ------ | ----------------- | ----------------------------------- |
| `text` | string | 最大 200,000 字符 | 加密时是明文，解密时是密文          |
| `key`  | string | 附加输入框        | 密钥，长度由「长度（bit）」决定     |
| `iv`   | string | 附加输入框        | **仅 CBC 必填**；GCM 留空会自动生成 |

密钥与 IV 走**独立的附加输入框**，**只在浏览器内存里使用**。

## 输出

| 字段   | 类型   | 说明                                                        |
| ------ | ------ | ----------------------------------------------------------- |
| `text` | string | `<iv(base64)>.<密文(base64)>`；GCM 的认证标签已附在密文尾部 |

解密时 **IV 从密文前缀读取**，输入框里的 IV 会被忽略（这样密文自带足够信息）。

## 选项

| 选项        | 取值                | 默认    | 说明                                 |
| ----------- | ------------------- | ------- | ------------------------------------ |
| `method`    | GCM / CBC           | GCM     | 加密模式，**推荐 GCM**               |
| `bits`      | 128 / 192 / 256     | 128     | 密钥位数，对应 16 / 24 / 32 字节     |
| `direction` | encrypt / decrypt   | encrypt | 加密或解密                           |
| `encoding`  | utf8 / hex / base64 | utf8    | 密钥（与 IV 输入框）的字符串表示方式 |

## 限制

- **GCM 自带完整性校验**：密文或认证标签被改动一个 bit，解密就会失败并报错 —— 这是选择 GCM 的主要理由
- **CBC 不提供完整性**：WebCrypto 的 AES-CBC 会自动做 PKCS#7 填充，但密文被篡改时不会报错（可能解出乱码），**除非你能自行加 MAC，否则请用 GCM**
- **为什么提示「不要用 AES-ECB」**：ECB 对每个 16 字节分组独立加密、不使用 IV，**相同的明文分组会产出相同的密文分组**，从而泄漏数据的结构与重复模式（经典例子是加密位图后仍能看出轮廓）。ECB 既没有 IV 的随机化，更没有任何认证，因此本工具**不提供 ECB**；要「确定的、可复现的密文」请用 CBC + 固定 IV，但这同样不安全
- IV 复用是致命的：GCM 下**同一密钥重复使用同一 IV** 会彻底破坏安全性。本工具在 IV 留空时用 `crypto.getRandomValues` 生成随机 IV，请勿手工固定 GCM 的 IV 去加密多条消息
- CBC 的 IV 必须是 16 字节；GCM 的 IV 推荐 12 字节
- 输入上限 200,000 字符

## 数据流向

**纯本地处理。** 明文、密钥、IV 全部只在浏览器内存中流转：加解密由浏览器的 **WebCrypto**（`crypto.subtle`）完成，
**不发起任何网络请求、不写入 localStorage，密钥与明文绝不上传**。
`meta.api = false`，无需自备 API/Key。

## 示例

输入（默认 GCM / 128 / utf8，IV 留空）：

```text
这是一段需要加密的明文。
```

密钥：

```text
aeskey0123456789
```

输出（IV 前缀每次不同）：

```text
<b64 iv>.<b64 密文 + 认证标签>
```
