# 多时区会议时间

约跨时区会议时，把一个「源时区下的开会时间」换算成每个参与方的当地时间，并自动标注是不是在对方的工作时间（9–17 点）或深夜（22 点–次日 6 点）。

## 用途

和国外同事约会议最容易踩的坑就是「我这边下午三点，你那边几点？是不是半夜？」。
输入一个时间和源时区，再贴上参与方时区列表，直接看谁方便、谁要熬夜。

## 输入

| 字段         | 类型   | 说明                                        |
| ------------ | ------ | ------------------------------------------- |
| `text`       | string | 会议时间，格式 `YYYY-MM-DD HH:mm`（或用 T） |
| `sourceZone` | string | 源时区（IANA 名），默认 `Asia/Shanghai`     |
| `zones`      | string | 参与方时区，**每行一个** IANA 名            |

空的会议时间不产出任何内容。

## 时段标注

| 标签     | 当地小时范围    |
| -------- | --------------- |
| 工作时间 | 9:00–17:00      |
| 深夜     | 22:00–次日 6:00 |
| 其他时段 | 其余            |

## 输出

```text
源时区 Asia/Shanghai：2026-09-28 周一 14:00

参与方当地时间：
  America/New_York：2026-09-28 周一 02:00 —— 深夜
  Europe/London：2026-09-28 周一 07:00 —— 其他时段
```

## 常见 IANA 时区名

| 城市        | 时区名                |
| ----------- | --------------------- |
| 北京 / 上海 | `Asia/Shanghai`       |
| 东京        | `Asia/Tokyo`          |
| 伦敦        | `Europe/London`       |
| 巴黎        | `Europe/Paris`        |
| 纽约        | `America/New_York`    |
| 洛杉矶      | `America/Los_Angeles` |
| 悉尼        | `Australia/Sydney`    |
| UTC         | `UTC`                 |

## 错误处理

- 时间格式不是 `YYYY-MM-DD HH:mm`：中文报错。
- 时区不是合法 IANA 名：中文报错。
- 输入超过 200,000 字符：中文报错。

## 限制

- 基于 `Intl.DateTimeFormat`，依赖浏览器自带的 IANA 时区数据库；换算自动处理夏令时。
- 不做「自动找大家都在工作时间的时段」，只做单向换算。
- 参与方时区列表会自动去空行、去重保序。

## 数据流向

**纯本地处理。** 仅用 `Intl.DateTimeFormat` 做时区换算，不发网络请求。`meta.api = false`。
