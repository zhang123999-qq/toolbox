# JSON Diff

两份 JSON 的**差异对比**：统一排版后再比，剩下的差异就是字段差异。

## 用途

接口改版前后、配置两份、mock 与真实响应之间的差异肉眼难找。粘两段进来，
`-` 行是改动前、`+` 行是改动后、行首空格表示未变。

## 输入

| 字段    | 类型   | 约束                          |
| ------- | ------ | ----------------------------- |
| `text`  | string | 改动前的 JSON，≤ 500,000 字符 |
| `textB` | string | 改动后的 JSON，≤ 500,000 字符 |

`textB` 由模板的 `extraInputs` 渲染成第二个输入框（界面标签「新版」）。

## 输出

| 字段   | 类型   | 说明                         |
| ------ | ------ | ---------------------------- |
| `text` | string | 差异文本；两侧都空时返回空串 |

```
  {
-   "tools": 870
+   "tools": 871
    "name": "工具库"
  }
```

两份内容一致时输出：`两份 JSON 内容相同`。

## 选项

| 选项       | 取值             | 默认    | 说明                                   |
| ---------- | ---------------- | ------- | -------------------------------------- |
| `mode`     | `line` \| `char` | `line`  | 行级 / 字符级粒度                      |
| `sortKeys` | boolean          | `false` | 对比前先按键名归一化，忽略书写顺序差异 |

## 限制

- 输出是**便于阅读的差异文本**，不是可直接 `git apply` 的补丁
- 单侧上限 500,000 字符：字符级 diff 的代价随长度超线性增长，比纯文本 Diff 低一级
- 两侧都空返回空串；只有一侧有内容会抛 `JsonDiffError`（无从对比）
- 任一侧非法 JSON 抛 `JsonDiffError`，消息里标明是左还是右

## 数据流向

**纯本地处理。** 输入内容仅在浏览器内存中处理，不发送任何网络请求，不写入服务端。
`meta.api = false`，无需自备 API/Key。

## 示例

输入（左）：`{"name":"工具库","tools":870}`
输入（右）：`{"name":"工具库","tools":871}`

输出：

```
  {
    "name": "工具库",
-   "tools": 870
+   "tools": 871
  }
```
