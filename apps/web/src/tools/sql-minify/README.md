# SQL 压缩

去掉注释与多余空白，把 SQL 压成单行。全程纯 TypeScript 自实现。

## 用途

把排版好的 SQL 压回一行，用于埋点日志、SQL 模板、配置文件瘦身以及对外的接口样例。

## 输入

| 字段   | 类型   | 约束              |
| ------ | ------ | ----------------- |
| `text` | string | 最大 200,000 字符 |

## 输出

| 字段   | 类型   | 说明                     |
| ------ | ------ | ------------------------ |
| `text` | string | 单行 SQL；空输入返回空串 |

## 选项

无。压缩只保留「必需」空格，不提供额外开关。

## 处理规则

1. **注释**：`--`、`#`（MySQL 行注释）与 `/* */` 块注释全部删除。
2. **空白**：换行、制表、连续空格压成「零个或一个」空格——只在两个名字之间、
   名字与符号之间保留一个空格。
3. **符号**：`,` `;` `)` `.` `::` 前不加空格；`(` `[` `,` `;` `.` `::` 后不加空格。
4. **函数与类型**：`COUNT(*)`、`VARCHAR(64)` 这类名单内的名字后紧跟括号，不留空格。
5. **字符串**：`'a   b'` 这类字面量内部的空白、注释符号一律不动；同理 `` ` `` 与 `"`
   包裹的标识符引用内容也保持原样。
6. **运算符**：`a > 1` 两侧的空格保留，`-1`（负号）不会被贴到前一个 token 上，避免语义变化。

## 限制

- 不是完整解析器，不进行方言校验；压缩前会检查括号配对与引号闭合。
- 只收紧「常见函数 / 类型名单」后的括号；自定义函数名后的括号会保留一个空格，
  以保证 `INSERT INTO t (a,b)` 这类写法不被误合并。
- 运算符两侧的空格不做进一步压缩（比 `sql-minifier` 类库略长，但语义更安全）。
- MySQL 的 `LOAD DATA`、预处理语句等方言特有语法按普通 token 处理，压缩后需自行复核。
- 括号必须配对；不配对时抛 `SqlMinifyError`，消息里带「第 N 行第 M 列」。

## 异常

| 场景                  | 行为                                  |
| --------------------- | ------------------------------------- |
| 输入为空              | 返回空字符串                          |
| 输入超过 200,000 字符 | 抛 `SqlMinifyError`                   |
| 括号不配对            | 抛 `SqlMinifyError`，带行列的中文提示 |
| 字符串 / 引号未闭合   | 抛 `SqlMinifyError`，带行列的中文提示 |
| 块注释未闭合          | 抛 `SqlMinifyError`，带行列的中文提示 |

## 数据流向

**纯本地处理。** 输入内容仅在浏览器内存中处理，不发送任何网络请求，不写入服务端。
`meta.api = false`，无需自备 API/Key。

## 示例

输入：

```sql
-- 查活跃用户
SELECT u.id,
       COUNT(*) AS cnt
FROM users u
WHERE u.age > 18 AND u.status = 'active'
ORDER BY cnt DESC
```

输出：

```sql
SELECT u.id,COUNT(*) AS cnt FROM users u WHERE u.age > 18 AND u.status = 'active' ORDER BY cnt DESC
```
